# M0-R3 每晚 Bench 精简

- 里程碑：M0 评审后续　依赖：M0-R　建议分支：`bench-nightly-trim`
- **阻塞 M1：否**（建议尽早做，在第一次每晚运行前后合并）

## 背景

`.github/workflows/bench.yml` 写死了基线 `5b23d8c`。每次运行都要额外检出旧代码、安装依赖，先跑基线再跑候选，还扫描 R=2/3/4，耗时 17–22 分钟，超过“每晚 Full + Bench ≤ 20 分钟”的预算。按每晚运行算，一个月约 600 分钟，占 2000 分钟额度的 30%。

## 范围

- 每晚（schedule）：只跑当前 main 的候选，默认 R，检查 M0-12/M0-13/M0-13a 的绝对预算（热读 p95 ≤ 1s、≤100 行预览/确认 p95 ≤ 2s、主线程事件循环阻塞最长 ≤ 100ms、p99 ≤ 50ms），结果写入 job summary 和 artifact。
- 手动（workflow_dispatch）：新增输入 `baseline`（commit，默认空，为空时不跑基线）和 `sweep`（布尔，默认否）。只有任务验收需要做回退对比时（M0-13a 的 p50 ≤10% 规则），才手动带上基线和同 runner 对比。
- 去掉写死的 `5b23d8c`。

## 验收标准

- 每晚运行墙钟 ≤ 10 分钟（给出一次实测 run 链接）。
- 手动带 `baseline` 的运行产出与现在相同的对比表（给出一次实测链接）。
- 回退判定规则只有一套（M0-13a 现行规则），没有并存的第二套。
- CI 绿。

## 性能考虑

只改 CI 编排，不改基准的数据量或预算。
