# M0-R4 Windows 上 INVALID_SNAPSHOT 间歇失败

- 里程碑：M0 评审后续　依赖：M0-R　建议分支：`windows-invalid-snapshot`
- **阻塞 M1：否**；**M2 前置门禁**：M2 导入原账套之前必须完成（只读旧账读取器是 M2 的导入入口）

## 背景

`packages/infra/src/legacy/teaching.ts:120-155` 在头部、sidecar 或身份校验失败时报 `INVALID_SNAPSHOT`。在 Windows 本机上，相关测试（`legacy-teaching.test.ts:50,70,90-123`）偶尔失败；CI 只跑 Linux，从未失败。推测原因是 Windows 上文件句柄或 WAL sidecar 的时序竞争。

## 只读边界（必须遵守）

- 读取器是只读消费者：读取时**不得** checkpoint 源快照、删除或改写 sidecar（`-wal`/`-shm`）、修改源文件，也不得以任何方式写 4173 原账套和 ID3 草稿。
- checkpoint 只允许用在两处：测试中独立生成的夹具，以及快照**生产**步骤（生成快照的一方在交付前完成）。读取端可以在不写源文件的前提下等待句柄释放或只读重试。

## 范围

1. 先复现：在 Windows 上循环跑相关测试，记录失败率和失败时的具体校验点。
2. 能复现：按证据修复根因，**不能放宽校验**。根因在夹具或快照生产步骤就在那里修；在读取器就只能改读取方式（例如只读/不可变方式打开、等待句柄释放后重试读取），不能改源文件。
3. 无法复现（D9）：不要求找到根因，按下面“无法复现时的结案证据”结案。

## 验收标准

两种结案方式共同要求：

- 校验条件没有被删除或放宽。
- 测试证明读取前后源快照文件及其 sidecar 的内容和 mtime 都不变（只读验收不变）。
- Linux CI 绿。

能复现时：

- PR 描述写明复现方法、修复前失败率、根因证据。
- 修复后 Windows 循环 50 次 0 失败（贴出本机输出摘要）。

无法复现时的结案证据（D9，三项都要有）：

1. **压测证据**：提供 Windows 上可手动运行、也可放进每晚任务的循环命令（例如原测试循环 50 次、隔离夹具压测 500 次），PR 描述贴出运行结果摘要。
2. **诊断信息**：`INVALID_SNAPSHOT` 错误写明是哪一项检查失败（头部、sidecar、身份等），并附带该文件两次读取时的 size、mtime、ino（Windows 用文件 ID），以便以后出现时能直接定位；不输出路径以外的敏感内容。有测试覆盖每类失败的诊断字段。
3. **不放宽校验的加固**：例如读取时用只读/不可变方式打开、对同一文件句柄做前后身份比对；任何加固都不能删除或放宽现有检查，也不能写源文件。

## 性能考虑

读取器只在导入时使用，不在热路径上；修复不应在每次读取时增加超过 50ms 的等待。
