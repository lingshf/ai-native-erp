# M1-R3 账龄/余额容量：带历史与并发的基准

- 里程碑：M1 评审后续　依赖：M1-R　建议分支：`trade-report-capacity`
- 冲突域：bench/CI, storage
- **阻塞 v0.2.0：否**

## 背景

M1-07 基准（`docs/performance/trade-e2e-bench.md`）在 10 万未结项上当前账龄 p95 最高 602ms（预算 1000ms 的 60%），因为每次请求都聚合全部未结项求合计。容量夹具没有核销/调整历史，也没有并发请求。见 [M1 评审 §4](../reviews/M1.md)。

## 范围

- 基准夹具增加核销与调整历史（例如每个未结项平均 2 次核销、5% 有贷项/取消），并加 3 个并发的报表请求场景。
- 如果任一场景超过 D18 的 80% 贴线值，再做优化（例如合计改为按索引聚合或分页合计分离），不引入重放缓存（路线图约束）。
- 预算和阈值不变。

## 验收标准

1. Bench 给出新场景的实测 run 链接，全部在预算内。
2. 如有优化：行为测试证明合计与历史余额结果不变。
3. Bench 墙钟仍 ≤ 20 分钟。
