# M1-05 预付/预收及应用、贷项、专用取消与反向

- 里程碑：M1　依赖：M1-04　建议分支：`trade-prepayments-credits-cancel`

## 目标

实现 [FR-T06、FR-T07](../requirements.md)。

## 范围

- AP 预付款、AR 预收（不确认收入）与正式发票分开；同伙伴同币种预付/贷项应用到发票，受两边剩余额与 `revision` 约束，输出控制科目转移与结算链；部分应用可继续，重复不多冲。
- 非库存贷项：关联原发票，按原行价格/税和累计可贷数量分配，形成可应用/退款的反向未结项。
- 专用取消：完整未结的发票/贷项/预付可取消，恢复原发票可贷量/订单数量；结算/应用可专用反向并恢复余额；需新来源号、原因、日期不早于相关对象最晚事件日；有效后续依赖未撤销前拒绝；不自动级联。通用手工冲销（M0-10）拒绝作用于贸易凭证。
- web：预付/预收录入、应用、贷项、取消入口。

行为参考：stash 中 `enterprise-trade.mjs` 对应部分及测试。

## 验收标准

- FR-T06/T07 每条规则有测试；取消/反向后余额与链路正确；依赖存在时取消被拒。
- CI 绿。

## 性能考虑

依赖检查走索引：`settlements(open_item_id)`、`trade_document_lines(source_line_id)`；确认 p95 ≤ 2s。

## 测试要求

application 层为主；本任务规则多，可拆两个 PR（预付/应用；贷项/取消），在 PR 描述说明。
