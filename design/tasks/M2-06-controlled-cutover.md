# M2-06 受控切换与回退

- 里程碑：M2　依赖：M2-05　建议分支：`controlled-cutover`
- 冲突域：admin-cli, docs/runbook
- **开工门禁**：M0-R4、M0-R5 都已合并（M2-01、M2-02 显式依赖两者，其余 M2 任务经依赖传递继承）。
- **数据**：开发、CI 和 Bench 只用虚构夹具。对真实旧账（4173 原账套、ID3 草稿、旧 checkout）的任何操作都需要 README“待用户决定”中对应的授权，本任务的开发与验收不需要真实数据。
- **真实切换**：需要决定 B，并且 M2-05 的真实演练已通过（A、C）；由用户（操作员）在维护窗执行，开发角色不执行。虚构切换/回退演练不受此限制，可以先做完。

## 范围

- **写入基线**：M2-04 `--confirm` 记录的基线 W（`write_seq`，见 M2-03）。判断“导入后是否有写入”只比较 `write_seq` 与 W，不用内容摘要——写入后又恢复原值也会使序号增加。
- **绑定基线的目标备份**：`cutover` 在持锁状态下调用 M0-R5 备份新目标库，并把备份文件 SHA、run ID 和 W 写进 run 行和备份 manifest；只有这份备份算数。验证时恢复到临时位置，确认其 run ID、`write_seq` 等于 W、完整性检查通过。不接受任意同版本且完整的备份。
- **切换**（写入手册；`cutover --target …` 只做检查和配置切换，不负责停旧服务）：
  1. 用户停止 4173（停写）；
  2. M2-01 对原目录取最终快照和旧账备份（源静止检查必须通过）；
  3. M2-03 导入、M2-04 `--confirm` 判定 `通过`；
  4. `cutover` 取得 M0-R5 的独占维护锁并持有到配置写完：确认 `write_seq` 等于 W，生成并验证绑定基线的目标备份，再显式把运行时目标库配置写为新库路径（不按文件名推断）；释放锁后用户启动新运行时并抽查。
- **回退**（`cutover --rollback`）：
  1. 用户先停止新运行时；
  2. 工具取得独占维护锁并一直持有到回退完成，期间任何运行时或 CLI 写入都会被拒绝；
  3. 读取 `write_seq` 与 W 比较。只要大于 W（任何业务写入，包括不产生 GL 的草稿编辑、主数据、配置、队列或状态变化，以及写入后又恢复原值），就拒绝回退，提示需要另行批准的反向修复，不能用旧备份覆盖而丢掉增量；
  4. 等于 W：把运行时配置恢复为切换前的值，把目标库 run 标记为 `retired`（运行时拒绝打开），释放锁；用户重启旧服务。
- 切换后旧源、快照和旧账备份保持只读归档。

## 验收标准

1. 虚构完整切换 + 回退演练（自动化测试）：没有写入时回退成功，配置恢复，目标标记 `retired`。
2. 回退前做以下任一操作，回退都被拒绝：新增凭证、编辑草稿、改主数据、改配置、只改状态（不产生 GL）、新增草稿后再删除、改设置后再改回原值。
3. 回退检查持锁期间，运行时尝试写入：被拒绝或阻塞，`write_seq` 不变，回退结果正确。
4. `cutover` 拒绝：核对不是 `通过`、`write_seq` 不等于 W、绑定备份生成或验证失败；提供另一份同版本且完整、但未绑定本 run/基线的备份也不被接受。
5. 真实切换（授权后由用户执行）的结果由用户确认，在 M2-R 中如实记录。

## 性能考虑

维护窗时长约等于快照 + 导入 + 核对 + 目标备份，按 M2-05 的 Bench 估算并写进手册（100 万 GL 行目标 ≤ 15 分钟）。写入序号比较是 O(1)；绑定备份的耗时计入维护窗。
