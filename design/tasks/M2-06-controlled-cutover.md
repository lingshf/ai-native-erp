# M2-06 受控切换与回退

- 里程碑：M2　依赖：M2-05　建议分支：`controlled-cutover`
- 冲突域：admin-cli, docs/runbook
- **开工门禁**：M0-R4、M0-R5 都已合并（M2-01、M2-02 显式依赖两者，其余 M2 任务经依赖传递继承）。
- **数据**：开发、CI 和 Bench 只用虚构夹具。对真实旧账（4173 原账套、ID3 草稿、旧 checkout）的任何操作都需要 README“待用户决定”中对应的授权，本任务的开发与验收不需要真实数据。
- **真实切换**：需要决定 B，并且 M2-05 的真实演练已通过（A、C）；由用户（操作员）在维护窗执行，开发角色不执行。虚构切换/回退演练不受此限制，可以先做完。

## 范围

- **持久写入基线**：M2-04 核对为 `通过` 时，对目标库所有业务表（凭证含草稿、单据、主数据、配置、队列、期间状态等；只排除 run 表本身）计算逻辑摘要，写入 run 行，作为“导入后未被写入”的基线。
- **切换**（写入手册；`cutover --target …` 只做检查和配置切换，不负责停旧服务）：
  1. 用户停止 4173（停写）；
  2. M2-01 对原目录取最终快照和旧账备份（源静止检查必须通过）；
  3. M2-03 导入、M2-04 核对为 `通过`；M0-R5 备份并验证新目标库；
  4. `cutover` 持有 M0-R5 的独占维护锁，复核基线摘要未变，然后显式把运行时目标库配置写为新库路径（不按文件名推断），释放锁后用户启动新运行时并抽查。
- **回退**（`cutover --rollback`）：
  1. 用户先停止新运行时；
  2. 工具取得独占维护锁并一直持有到回退完成，期间任何运行时或 CLI 写入都会被拒绝；
  3. 重新计算业务表逻辑摘要，与基线比较。只要有差异（包括不产生 GL 的写入，例如编辑草稿、改主数据或配置、队列或状态变化），就拒绝回退，提示需要另行批准的反向修复，不能用旧备份覆盖而丢掉增量；
  4. 摘要一致：把运行时配置恢复为切换前的值，把目标库 run 标记为 `retired`（运行时拒绝打开），释放锁；用户重启旧服务。
- 切换后旧源、快照和旧账备份保持只读归档。

## 验收标准

1. 虚构完整切换 + 回退演练（自动化测试）：没有写入时回退成功，配置恢复，目标标记 `retired`。
2. 回退前做以下任一操作，回退都被拒绝：新增凭证、编辑草稿、改主数据、改配置、只改状态（不产生 GL）。
3. 回退检查持锁期间，运行时尝试写入：被拒绝或阻塞，摘要不变，回退结果正确。
4. `cutover` 拒绝：核对不是 `通过`、新目标库备份缺失或验证失败、基线摘要已变。
5. 真实切换（授权后由用户执行）的结果由用户确认，在 M2-R 中如实记录。

## 性能考虑

维护窗时长约等于快照 + 导入 + 核对 + 目标备份，按 M2-05 的 Bench 估算并写进手册（100 万 GL 行目标 ≤ 15 分钟）。摘要按表流式计算，100 万行 ≤ 60s。
