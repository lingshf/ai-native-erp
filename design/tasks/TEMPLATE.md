设计角色写新任务书时复制本模板（S8 回顾，D258）。结构按 TINV-01、PROC-04 的写法归纳。不适用的节写“不适用”并说明原因，不要删掉。

- Sprint：Sn（[计划](README.md#…)）　依赖：…　建议分支：`<id>-<slug>`

  - <域>：`path`（改什么）；
  - 共享单文件：`…`（顺序与门禁见 Sprint 泳道“共享单文件”列）；

- 类型：…

## 验收标准

编号列出；每条都能用测试、日志或 `git diff` 判定。契约变化只在响应 schema 上增加字段；请求 schema 与其他共享的严格 schema 不改，除非任务明确要求并写明兼容验收。

## 证据要求

- 真实 Chrome 与 E2E：按[路线图 §5 UI PR 证据清单](../roadmap.md#5-团队流程) 1–8 项，请求评审前逐项勾选，包括：
  - 第 7 项：断言对照实际渲染与 schema 字段位置，列出“断言 → `file:line`”；

- PG-05：base 为 PR 实际 base；数字绑定到最终送审的 head，与取证 head 分开写。
- 不需要真实 Chrome 的任务写明理由，例如“只改注释，构建产物字节不变”。
