# E2E-01 并发真实 Chrome E2E 是否互相干扰

- Sprint：S6（[计划](README.md#s6订单列表与保存前预览--s5-遗留收尾建议-v060)）　依赖：[FLAKE-03](FLAKE-03-navigate-target-page-ready.md) 合并（同冲突域；先消除已证实的提前返回，避免它混进实验结果）　建议分支：`e2e-01-concurrency-check`
- 冲突域：tests:e2e（只读核对；若要提交，只提交本文要求的报告脚本或说明，不改测试行为）。实验需要**整台机器**：运行期间没有其他 session 跑真实 Chrome、Playwright 或 vitest slow。
- 类型：调查
- 来源：[S5 回顾议题 2](../reviews/S5.md#议题-2真实-chrome-e2e-独占时段的排队成本)。D115 / D118 的独占时段在没有干扰证据时采用；S5 中排队约 40–52 分钟 / 次。

## 范围

1. **静态核对**：列出 `trade-gui-*`、`migration-gui.slow` 及其支持代码使用的端口（固定 / 随机）、临时目录与账套文件、Chrome 用户目录、`ERP_E2E_ARTIFACTS` 路径。逐项写明两个 worktree 同时运行时是否可能相撞（附 `path:line`）。
2. **受控实验**：在同一个精确 head 上，次数预先写在 PR 描述里，不中途追加：
   - 串行：单 worktree 连续跑 N 次（建议 N = 5）；
   - 并发：两个 worktree 同时各跑 N 次；
   - 每次记录：通过 / 失败、失败用例与断言、各文件的 Vitest `Duration`、开始前外部进程数（D118 口径）、运行中每 10 s 的 CPU 采样。
3. **结论**按[路线图 §4](../roadmap.md#4-ci-与测试策略设计角色牵头)区分观察 / 推断 / 归因：
   - 静态核对发现相撞的共享资源：列出，作为修复任务报告设计角色立项（不在本任务修）；
   - 未发现相撞、并发 N 次没有新增失败：只能说“本实验未观察到干扰”，交协调者决定是否放宽独占时段（例如允许 2 个并发）；
   - 并发出现失败：保留全部日志，标为观察，不归因，独占时段不变。

## 验收标准

1. 静态核对表完整，每项有 `path:line`。
2. 2N 次运行的日志全部在 gist 中（含失败），首尾有精确 head 与空的 `status --porcelain`。
3. 结论段只使用上面三种之一的表述，不出现“证明没有干扰”。
4. 不改任何测试的行为、超时或重试（D11）。
