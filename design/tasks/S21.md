## 为什么是这三项

- **SLOT-04**：DEMO-18、DEMO-19 两次窗口处置都与调用位置和步骤边界有关（D496–D499）。DEMO-19 的 4b 从 tool worktree 调用（`-BaseRoot` 与步骤文件都在 app，只命中 SLOT-04 的 R-steps），步骤脚本在预检、构建、采样之后才因路径不存在失败。在工具里挡住，比靠开窗申请里的文字提醒可靠。dist 检查改用 RUNMAIN-01 的脚本后，runner 与 Demo 的 `run-main` 只剩一份规则（`assert-web-dist.ps1:3` 已写明“Same rule as slot-run.ps1:154-162”）。
- **FLAKE-08**：main Full 红会暂停合并（D456）。这次失败的函数栈全部在 `@tanstack/virtual-core` 的防抖定时器里，与被归因的 `shell-targets.test.ts`（只读 CSS 文本，5 ms）无关，是前面某个 jsdom 测试留下的定时器在环境拆除后触发（见任务书“现状”）。不根治，任何经过虚拟列表的测试都可能再次让无关分片变红。
- **TLIST-05**：“刷新列表”系列（TLIST-01–04）剩下的两页中，业务事件可以不先拆分就加（结算须先拆 `SettlementEntry`）。业务事件的“待转队列”是用户确认过账前要看的工作队列，转入与撤回可能由另一个标签页或 AI 助手完成，现在只能切换视图或按 F5（会丢失所选状态）重读。
- **三项都不加迁移**，冲突域不相交，可同时派给 3 名开发（见“泳道”）。

- **用户可见变化**：每个 PR 正文须有“用户可见变化”一节；SLOT-04、FLAKE-08、DOC-21 写“无”。
- **中英双语、红 / 绿主题、键盘可用、教学模式可关闭**：

适用于改动 Web 的 TLIST-05（L10）。SLOT-04、FLAKE-08 不改 `packages/web/src/` 与构建配置，打包不变由“范围”不变量（`git diff --name-only`）证明，不另测字节。

- **上限**（超出即停下报设计角色与协调者，不自行放宽）：
