## 现状（main `1bb9dbb`）

- `docs/release/README.md:85` 要求可复制命令用替身跑过成功与失败分支（S5 行动项 10），但没有规定失败分支跑哪些。S7 中 #156、#164 共 4 轮打回，都是评审用临时夹具复现出作者没跑到的边界：隐藏文件未枚举、读取失败不中止、删光文件仍报“未变”、抛错后跳过后置哈希、第二个 seed 前缺归属检查、递归删除共享目录、命令里写入了字面 `\n` 无法复制（见 [S7 回顾 议题 3](../reviews/S7-retro.md#议题-3文档-pr-多轮评审)）。

## 范围

1. 在 `docs/release/README.md` 发布 PR 清单第 85 行条目下增加“固定负例组”，请求评审前对文档中每个可执行块逐项跑（不适用的项写“不适用”及理由）：
   1. 目标目录为空；
   2. 含隐藏文件；
   3. 文件不可读或被独占锁定；
   4. 执行中途抛错（`finally` / 后置检查仍执行，原始异常与检查结果都报告）；
   5. 端口或监听进程归属在两步之间变化；
   6. 从渲染后的文档复制到新终端执行一次（发现字面转义、拼行、不可见字符）。
2. 每项的输出摘要写进 PR 正文；只写“已跑”不算。
3. `docs/demo/TEMPLATE.md` 的“替身验证”引用这一组，不重复全文。
4. 条目末尾注明来源（“S7 回顾行动项 5”）。

## 不在范围

- 回补历史文档；改 `design/`（设计角色的对应自查已写入路线图 §5）。

## 验收标准

1. 六项负例在清单中可逐项勾选，并说明“不适用”的写法。
2. 用 #156 与 #164 评审中复现过的三个缺陷（删光文件报“未变”、抛错后跳过后置哈希、字面 `\n`）各做一个夹具，证明按清单跑会发现它们；输出摘要写进 PR 正文。
3. 只改上述两个文件。
