## 方案

1. **活动的待办表移出，一张表一个文件**，放在 `design/tasks/backlog/` 下：`KDOC.md`、`KGAP.md`、`SEC.md`、`BUG.md`、`MCF.md`。每个文件含原节的引言与表格，文本不变。不同表的状态同步改不同的文件，可以并行合并。
2. **里程碑收尾检查（D566）移到 `design/tasks/milestone-closeout.md`**：这是流程规则，不是状态表；移出后本文件不再混放规则。
3. **原标题保留为桩**：本文件中每个被移走的二级、三级标题原样保留，下面只写一行“已移至 [X](…)”。原锚点仍然有效，入站链接（包括历史评审文件中的）不必改；新写的链接直接指向新文件。
4. **“下一个可用编号”只写在当前 Sprint 文件中**（现为 [S25.md](S25.md#s25-期间决定)）；本文件的 Sprint 一节只链接过去，不再重复编号。新增决定的 PR 本来就要重新生成 `design/decisions.md`（MCF-14），这一步已经是串行点；不再额外改本文件。
5. **不动的部分**：M0–S24 各节（入站链接多、几乎不再改，搬走没有并行收益）；派发顺序与决定记录（短，且很少改）。M2 一节在 M2 启动时再按同样办法评估。
6. **规则不变**：本文件开头“团队唯一待办”的说法改为“本文件与 `backlog/` 下各文件共同构成团队唯一待办”；修改权限（只由设计角色修改，执行字段按 D557）同样适用于新文件。

预计效果：本文件约减到 920 行；常改的部分从约 200 行分散到 6 个文件，每个不超过 100 行。

## 实施时的验收

1. **纯搬移**：每个新文件的正文与原节去掉标题行后的文本相同，唯一例外是因文件移动而改写的相对链接；PR 正文附比对命令与输出（例如按 base 的行号区间用 `git show <base>:design/tasks/README.md` 截取后与新文件 `diff`），并逐条列出改写的链接（原文 → 新文），`diff` 中不得有清单以外的差异。
2. **链接不断**：对 base 上指向本文件的全部锚点（检索命令同上），在 head 上逐个确认目标标题仍存在（桩或原节）；新文件内部的相对链接（如 `../reviews/…`、`#文档缺口候选d567`）改成从新位置可达，并列出改动清单。
3. **开头规则**已按第 6 条改写；当前的编号指针只在当前 Sprint 文件出现：取当前 Sprint 文件中指针行的编号 `D<N>`，`git grep -nE "下一个可用编号 D<N>([^0-9]|$)" -- design/tasks`（`<N>` 换成实际数字）只命中该文件一处。`design/tasks/README.md` 里残留的行内重复指针会被命中；历史节和旧 Sprint 文件中的旧编号指针（如 D518、D525）以及本方案文件都不会命中。
4. 重新生成决定索引：`node scripts/gen-decisions-index.mjs` 后 `--check` 退出码为 0。
5. 不改任何任务的状态、含义或顺序。
