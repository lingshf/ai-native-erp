1. 决定索引生成器不再静默漏行、误判记录，提及不再因行号漂移改动索引（MCF-21，含 D591 第 ③ 项）。

## 泳道（按冲突域）

| 泳道 | 负责 | 任务 | 冲突域 | 开工条件 |
| --- | --- | --- | --- | --- |
| A | Product/Design | MCF-21 → KGAP-03 → KGAP-05（设计页）→ KGAP-02（§6.1）；MCF-20 任务书穿插 | `scripts/gen-decisions-index.mjs`、`design/`（都要重新生成索引） | 本计划合并后；MCF-21 第一个合并，之后的 `design/` PR 都在 MCF-21 的新格式上重新生成 |
| B | 只读 Developer、Delivery/Release、Product/Design、QA | KGAP-01 事实复核与 QA 剩余演练 | 事实复核只读；QA 只在虚构夹具或临时账套中写临时数据（不碰真实账套，不是 M2-05 真实演练）；结论写在 PR 评论或复核记录中 | 本计划合并后立即 |
| C | Knowledge Lead | KGAP-01 矩阵更新 → KGAP-05 矩阵贸易行 → KGAP-02 `tradeoffs.md` 链接 | 只改 `docs/`（`docs/README.md`、`docs/tradeoffs.md`） | 各自依赖的 B 结论或 A 的设计 PR 合并后；同改 `docs/README.md`，串行 |
| D | Developer | MCF-20 | 新增 slow 测试文件、`scripts/test-shard-weights.json` | MCF-20 任务书合并后 |

- **开发名额**：上限 3。本 Sprint 占用 2：D 泳道 MCF-20 一人（写测试）；B 泳道 KGAP-01 的只读 Developer 事实复核一人（不写代码）。余 1 不预派。
- **迁移**：本 Sprint 没有涉及迁移的任务。计划期间若新增此类任务，不与其他迁移任务并行，按[迁移的串行集成](README.md#派发顺序)执行。
- **索引重新生成**：A、C 两泳道的 PR 都可能改 `design/decisions.md`。MCF-21 合并前，其他 PR 不改索引格式；后合并者 rebase 并重新生成，`--check` 通过后再请评审。
- **关键路径**：A 泳道串行，延误时按 D592 先砍 KGAP-02，再砍 KGAP-05；KGAP-01 延误时按页面逐格交付，未完成的格保持 partial。
- **状态同步**：`design/tasks/` 下的状态只由 Product/Design 更新，逐个提交；其他泳道在 PR 评论中给结论。
- **风险**：MCF-20 会在 `infra-browser` 分片中加新的真实 Chrome 文件，任务书须写明分片权重与满载耗时要求；KGAP-01 范围最大，依赖多个事实所有者。
