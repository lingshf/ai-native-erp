## 为什么是这几项

协调者要求从 S22 候选池中选三类：存量拆分、一项小步的界面打磨、经过 Demo 实用后的 SLOT 后续。

- **REFAC-13（存量拆分）**：`OrderLookup` 是 `trade-orders/` 中最后一个超过 ② 的函数，同目录的三个已由 REFAC-05b、REFAC-10、REFAC-11 拆完；S22 计划与 [S21 回顾 S23 候选 2](../reviews/S21-retro.md#s23-候选产品负责人建议) 都写明 S23 起排。候选池中更大的 `CompanyEvents`（563 行）等留到之后，一个 Sprint 一个。
- **TSET-01（小步打磨）**：TLIST-06 的“刷新列表”按 D513 不清草稿，于是“已选、但刷新后不在未结项中”成为会正常出现的状态；现在 KPI 显示“待加载”，用户又无法取消这一项（详见任务书“为什么”）。改动只在分配页签中加一个提示条与按钮，不改契约与服务端。**没有选“按开票状态排序”**：订单列表用服务端游标分页，排序要改 API 与契约，不是小步；而且它在 `trade-orders/` 中，与 REFAC-13 冲突。
- **SLOT-06（SLOT 后续）**：S22 候选池写明“`slot-run.ps1` 自动调用 `gate-snapshot.ps1`，等 SLOT-05 经过一次 Demo 实用后再评估”。DEMO-22 是 SLOT-05 的第一次 Demo 实用，所以 SLOT-06 以它为派发条件；派发前设计角色按 run-through 复核任务书，工具若有缺陷先修订任务书。经核对，自动调用**不需要**改规则表与 `procs.ps1`（快照子进程属 SR-R1，且 `pwsh` 不在候选进程名中），只改 `slot-run.ps1`。
- **三条泳道，都不加迁移**：三个任务的冲突域逐文件不相交（见“泳道”），可以并行；没有加迁移的任务。
