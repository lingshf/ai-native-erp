# M2-03 导入执行（写入新的目标库）

- 里程碑：M2　依赖：M2-02、M0-R5、M0-R1　建议分支：`legacy-import-execute`
- 冲突域：migrations(014)+migrations.ts, domain-posting, storage, admin-cli
- **前置门禁**：M0-R4（Windows `INVALID_SNAPSHOT`，只读读取器是导入入口）、M0-R5（目标库备份/恢复）必须已合并；未合并前本任务不得开工。
- **真实数据**：开发和 CI 只用虚构夹具。任何读取真实旧账（4173 原账套、ID3 草稿、旧 checkout）的操作都需要用户另行授权（见 D3）；本任务不需要真实数据。

## 背景

按 M2-02 的导入计划把旧账写入**一个新建的目标库文件**。不覆盖、不合并已有目标库；不双写；旧源保持只读。

## 范围

- 迁移 014：`legacy_import_runs`（快照 SHA、开始/结束时间、状态、计数）和 `legacy_refs`（旧对象类型 + 旧 ID → 目标 ID，唯一约束）。
- `legacy-import --snapshot-dir … --target <新库路径>`：目标路径必须不存在；先建库跑全部迁移，再导入。
- 写入走领域过账管道的“历史导入”入口：复用凭证平衡、期间、控制科目（登记的导入适配器）规则，不另写一套绕过校验的 SQL。关闭的期间：导入期间先按源状态建期间，凭证写完后再恢复关闭状态，过程在导入事务批次内完成，不对外暴露。
- 每批（≤ 5000 分录）一个事务；中断后重跑同一快照时按 `legacy_refs` 跳过已导入对象（幂等），换快照则拒绝。
- 导入完成时运行状态记为“待核对”；由 M2-04 加上导入后自动核对，核对通过才记为成功。

## 不做

- 不支持导入到已有业务数据的库；不做增量同步；不碰 4173 与旧 checkout。

## 涉及文件

`packages/infra/src/storage/migrations/014-*.sql`、`migrations.ts`、`packages/core/src/**/journals*`（导入入口）、`scripts/storage-admin.mjs`、新增导入集成测试。

## 验收标准

1. 夹具快照导入后：目标库试算（每月、每阶段）、科目余额、凭证/分录数、维度合计与源一致；草稿保持草稿；`legacy_refs` 覆盖每个导入对象。
2. 在第 N 批后强制中断再重跑：结果与一次跑完相同，无重复凭证。
3. 目标路径已存在、快照校验失败、换快照重跑：明确失败，目标或源不被修改。
4. 导入过程不新增绕过过账规则的写入路径（评审检查）；迁移从 007 升级到 014 的 CI 通过。

## 性能考虑

批量预编译语句、每批一个事务、导入期间不建非必要索引之外的东西（索引由迁移定义，不临时删建）。Bench：100 万 GL 行导入 ≤ 10 分钟、峰值 RSS ≤ 512MB；导入后热读预算与 M0 相同（试算 p95 ≤ 1s）。
