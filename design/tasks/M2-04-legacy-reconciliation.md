# M2-04 迁移核对报告

- 里程碑：M2　依赖：M2-03　建议分支：`legacy-reconciliation`
- 冲突域：legacy-import, admin-cli, web-ui:migration
- **前置门禁**：M0-R4（Windows `INVALID_SNAPSHOT`，只读读取器是导入入口）、M0-R5（目标库备份/恢复）必须已合并；未合并前本任务不得开工。
- **真实数据**：开发和 CI 只用虚构夹具。任何读取真实旧账（4173 原账套、ID3 草稿、旧 checkout）的操作都需要用户另行授权（见 D3）；本任务不需要真实数据。

## 背景

“备份不等于迁移完成”：切换前必须逐项核对，不能只比表行数（architecture.md 迁移原则）。本任务在 M2-03 的导入命令末尾接入自动核对（通过才把运行状态从“待核对”改为成功，不通过记为失败、目标库保留供排查但不得切换），并供 M2-05/M2-06 使用。

## 范围

- 核对函数：输入快照（经只读读取器）和目标库，输出结构化报告：
  - 每月每阶段试算、每科目余额（精确最小单位）；
  - 凭证数、分录数、按 `legacy_ref` 一一对应，缺失/多余清单；
  - 维度合计、期间状态（开/关）、草稿清单（含 ID3 仍为草稿）；
  - M2-02 报告中“不可映射/未导入”对象的数量，作为已知差异单列，不算通过也不算失败，需人工确认。
- CLI：`legacy-reconcile --snapshot-dir … --target …`，有差异时非零退出。
- Web 只读页 `/migration`：展示最近一次导入运行与核对报告（通过/差异），不提供任何写操作或切换按钮。

## 涉及文件

新增 `packages/infra/src/legacy/reconcile.ts` 及测试；`packages/web/src/pages/migration*` 及 labels（中/英）。

## 验收标准

1. 对 M2-03 夹具导入结果，报告全部一致。
2. 对目标库人为改一笔分录金额、删一张凭证、改期间状态：报告逐项指出差异并非零退出。
3. 页面中/英、红/绿、键盘可用；没有写操作。

## 性能考虑

按月份流式聚合，两侧各一次 GROUP BY，不逐行比对全部分录；逐行比对只针对 `legacy_refs` 缺失项。Bench：100 万 GL 行核对 ≤ 120s。页面只读最近一次报告（已存储结果），热读 p95 ≤ 1s。
