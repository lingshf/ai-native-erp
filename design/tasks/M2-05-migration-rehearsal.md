# M2-05 隔离试迁移演练与操作手册

- 里程碑：M2　依赖：M2-01、M2-04b（D25 全部完成：M2-03b 与 M2-04b 都已合并，D26）　建议分支：`migration-rehearsal`
- 冲突域：bench/CI, docs/runbook
- **开工门禁**：M0-R4、M0-R5 都已合并（M2-01、M2-02 显式依赖两者，其余 M2 任务经依赖传递继承）。
- **数据**：开发、CI 和 Bench 只用虚构夹具。对真实旧账（4173 原账套、ID3 草稿、旧 checkout）的任何操作都需要 README“待用户决定”中对应的授权，本任务的开发与验收不需要真实数据。

## 范围

- **虚构端到端**（进 Full，小夹具；100 万行版本进 Bench）：M2-01 生成快照和旧账备份 → M2-02 dry-run → M2-03 导入新库（显式选项）→ M2-03b 期初未结项 → M2-04 `--confirm`（附确认文件）→ M0-R5 备份并验证新目标库（绑定基线的备份由 M2-06 实现） → 用 M2-04 的 `--check` 只读路径抽查试算和总账。不能用默认 CLI 启动打开目标库，因为普通启动会初始化主数据。
- **操作手册** `docs/migration-runbook.md`（开发写，设计评审）：前置检查、每一步命令、预期输出、失败处理、回退条件、私有证据存放位置。写明：禁止直接操作运行中的 4173 目录和旧 checkout；需要哪项决定（A/B/C）才能执行哪一步。
- **真实演练**：需要决定 A（对用户提供的私有副本取快照）和决定 C（导入选项），导入范围含 AP/AR 控制科目时，还需要用户提供 M2-03b 的未结明细文件，且每个控制科目都有 `detail` 或 `empty` 声明（缺失即按 M2-03b 阻断口径 1 阻断）。在私有临时目标库上执行并产出核对报告，不切换，不停 4173，不改旧源。缺任一授权时，只能对真实快照做 dry-run（还需 A）或什么都不做。

## 验收标准

1. 虚构端到端在 Full 中通过，耗时 ≤ 60s。
2. Bench 分别记录快照、dry-run、导入、核对、目标备份的耗时，满足 M2-01..04 和 M0-R5 的预算。
3. 有授权时：真实演练核对为 `通过`；源的物理摘要前后不变。没有授权时本条记为“待授权”，不阻塞 M2-R，但阻塞 M2-06 的真实切换。

## 性能考虑

全链路不经过 API 进程，不影响在线热读。Bench 只在夜间或手动跑，不进 PR CI。
