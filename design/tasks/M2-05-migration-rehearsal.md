# M2-05 隔离试迁移演练与操作手册

- 里程碑：M2　依赖：M2-01、M2-03、M2-04　建议分支：`migration-rehearsal`
- 冲突域：bench/CI, docs/runbook
- **前置门禁**：M0-R4（Windows `INVALID_SNAPSHOT`，只读读取器是导入入口）、M0-R5（目标库备份/恢复）必须已合并；未合并前本任务不得开工。
- **真实数据**：本任务的 CI 部分只用虚构数据。对真实旧账的演练需要**用户授权（M2 决定点 A）**，由操作员在本机私有目录执行，证据只留在本机/会话，不进 Git。

## 范围

- 端到端脚本（夹具）：M2-01 生成快照 → M2-02 dry-run → M0-R5 备份 → M2-03 导入新库 → M2-04 核对 → 用新运行时以只读方式打开新库抽查试算和总账。进 Full（main）跑小夹具；100 万行版本进 Bench。
- 操作手册 `docs/migration-runbook.md`（开发写，设计评审）：前置检查、每一步命令、预期输出、失败处理、回退条件、私有证据存放位置；明确禁止操作 4173 进程与旧 checkout。
- 真实账演练（授权后）：只对**新取的私有快照**操作，导入到私有临时目标库，产出核对报告；不切换、不停 4173、不改旧源。

## 验收标准

1. 夹具端到端在 Full 中通过，总耗时 ≤ 60s。
2. Bench 记录 100 万 GL 行全链路耗时（快照、dry-run、导入、核对分别计时），满足 M2-01..04 各自预算。
3. 获得授权时：真实演练核对报告全部一致或只有已确认的已知差异；源物理摘要前后不变；ID3 仍为草稿。未获授权时本条记为“待授权”，不阻塞 M2-R，但阻塞 M2-06。

## 性能考虑

全链路不经过 API 进程，不影响在线热读；Bench 只在夜间/手动跑，不进 PR CI。
