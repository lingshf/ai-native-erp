# M2-02 旧账→目标库映射与 dry-run

- 里程碑：M2　依赖：M0-R4、M0-R5　建议分支：`legacy-import-mapping`
- 冲突域：legacy-import
- **开工门禁**：M0-R4、M0-R5 都已合并（M2-01、M2-02 显式依赖两者，其余 M2 任务经依赖传递继承）。
- **数据**：开发、CI 和 Bench 只用虚构夹具。对真实旧账（4173 原账套、ID3 草稿、旧 checkout）的任何操作都需要 README“待用户决定”中对应的授权，本任务的开发与验收不需要真实数据。

## 背景

旧账有两个库：教学库（科目、维度、期间、凭证/分录、分录维度、过账规则）和 Enterprise 库（公司、币种、配置版本、回执、来源事件、转账队列、封印、审计等）。导入前先要有一份确定性的导入计划和不写库的 dry-run 报告，在动真实账之前暴露问题和需要用户选择的地方。

## 范围

- 在 `packages/infra/src/legacy/` 下新增映射模块：输入是只读读取器打开的快照，输出导入计划（纯数据，不写库）。
- 固定规则（无需用户选择）：科目、维度、维度值、期间按编码一一映射；停用科目保持停用；已过账凭证作为历史凭证导入，保留原凭证 ID 为 `legacy_ref`，凭证日期、记账日期按原值，税日期等于凭证日期。
- **需要用户选择的项（决定 C）没有默认值**，计划函数和 CLI 都要求显式选项，缺少则拒绝：
  - `drafts`：草稿（含 ID3）`import-as-draft` 或 `skip`；
  - `receipts`、`source-events`、`transfer-queue`、`seals`、`audit`：分别 `import`（仅能在目标 schema 表达的部分）或 `archive-only`。
  - 虚构夹具测试显式传入选项；这只是测试数据，不代表真实操作的选择。
- dry-run CLI：`legacy-import --snapshot-dir … --dry-run`。dry-run **可以不传选项**：此时报告列出每个选项及受影响的对象数量，供用户做决定 C。传了选项则输出完整计划摘要。
- 报告内容：每类对象的源数量、可映射数量、不可映射清单（含原因码），按月、按科目的借贷合计。
- 未发布的 M-TRADE（stash）数据不在旧账里，不涉及。

## 不做

不写目标库（M2-03）。外币折算、暂记清理等后续里程碑的功能，遇到相关数据时报告为“不可映射”。

## 涉及文件

新增 `packages/infra/src/legacy/import-plan.ts`、`packages/infra/test/legacy-import-plan.test.ts`。本任务只导出函数和测试入口；CLI 接入放在 M2-03，避免与 M2-01 在 `admin-cli` 冲突。

## 验收标准

1. 虚构夹具（同月三阶段、跨月调整/冲销/结转、停用科目、维度、ID3 草稿、多页）+ 显式选项：两次运行得到逐字节相同的计划。
2. 计划中每月每科目借贷合计等于读取器试算；凭证数、分录数与源一致（草稿单列）。
3. 未传决定 C 选项：dry-run 输出选项清单和数量；非 dry-run 的计划生成被拒绝。
4. 不可映射数据（未知币种、孤儿分录、缺维度值）：按原因码列出，不抛异常、不静默丢弃。
5. 处理前后快照目录 SHA-256 不变。

## 性能考虑

游标分页流式读取（每批 ≤ 5000 行），内存与总量无关。Bench：100 万 GL 行 dry-run ≤ 120s，峰值 RSS ≤ 512MB。
