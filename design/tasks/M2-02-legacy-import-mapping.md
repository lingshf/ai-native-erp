# M2-02 旧账→目标库映射与 dry-run

- 里程碑：M2　依赖：M0-R4　建议分支：`legacy-import-mapping`
- 冲突域：legacy-import
- **前置门禁**：M0-R4（Windows `INVALID_SNAPSHOT`，只读读取器是导入入口）、M0-R5（目标库备份/恢复）必须已合并；未合并前本任务不得开工。
- **真实数据**：开发和 CI 只用虚构夹具。任何读取真实旧账（4173 原账套、ID3 草稿、旧 checkout）的操作都需要用户另行授权（见 D3）；本任务不需要真实数据。

## 背景

旧账有两个库：教学库（科目、维度、期间、凭证/分录、分录维度、过账规则）和 Enterprise 库（公司、币种、配置版本、回执、来源事件、转账队列、封印、审计等）。目标库是 M0 的新 schema。导入前先要有一份“确定性映射 + 不写库的 dry-run 报告”，把不能映射的数据在动真实账之前暴露出来。

## 范围

- 在 `packages/infra/src/legacy/` 下新增映射模块：输入是只读读取器打开的快照，输出是按目标 schema 组织的导入计划（公司、科目、维度、期间状态、凭证及分录、来源引用），纯数据，不写任何库。
- 映射规则（默认值，**标“待确认”的需用户确认**，见 M2 决定点）：
  - 科目、维度、维度值、期间（含关闭状态）按编码一一映射；停用科目保留停用状态。
  - 已过账凭证作为历史凭证导入，保留原凭证 ID 作为 `legacy_ref`，凭证日期、记账日期按原值；税日期缺省等于凭证日期。
  - 草稿（含 ID3）：**待确认**，默认作为草稿导入，不过账。
  - Enterprise 的回执、来源事件、封印、审计：**待确认**，默认只导入能在目标 schema 中表达的部分（回执与来源引用）；其余不导入，在报告中列出数量，快照保留为只读档案。
  - 未发布的 M-TRADE（stash）数据不在旧账里，不导入。
- dry-run CLI：`legacy-import --snapshot-dir … --dry-run`，输出 JSON 报告：每类对象的源数量/可映射数量/不可映射清单（含原因码），以及按月、按科目的借贷合计。

## 不做

- 不写目标库（M2-03 负责）。不做跨币种折算、暂记清理等 M0-R 列为后续里程碑的功能；遇到这类数据报告为“不可映射”。

## 涉及文件

新增 `packages/infra/src/legacy/import-plan.ts`、`packages/infra/test/legacy-import-plan.test.ts`；CLI 入口在 M2-03 合并时接入（本任务只导出函数和一个测试用入口），以免与 M2-01 的 `admin-cli` 冲突。

## 验收标准

1. 用已提交夹具（同月三阶段、跨月调整/冲销/结转、停用科目、维度、ID3 草稿、多页）得到确定的导入计划：两次运行逐字节相同。
2. 计划中每月每科目借贷合计与读取器试算一致；凭证数、分录数与源一致（草稿单列）。
3. 构造不可映射数据（未知币种、孤儿分录、维度值缺失）时，报告列出原因码，不抛异常、不丢数据。
4. 打开快照前后快照目录 SHA-256 不变。

## 性能考虑

流式按凭证批次读取（游标分页，每批 ≤ 5000 行），内存与总量无关。Bench：100 万 GL 行 dry-run ≤ 120s，进程峰值 RSS ≤ 512MB。
