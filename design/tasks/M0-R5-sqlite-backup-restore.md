# M0-R5 SQLite 目标库备份与恢复

- 里程碑：M0 评审后续　依赖：M0-R　建议分支：`sqlite-backup-restore`
- **阻塞 M1：否**；**阻塞 M2（真实账套迁入）**：真实数据进入目标库之前必须完成

## 背景

M0-15 退役了旧格式的备份/恢复和快照，目前新的 SQLite 目标库没有任何备份或恢复能力。单用户本机使用时，一旦误操作或磁盘损坏，就没有恢复手段。

## 范围

- 管理 CLI（沿用现有 storage admin CLI，不新建入口）：
  - `backup <path>`：用 SQLite 在线备份 API 或 `VACUUM INTO`，生成单个一致的文件，过程中服务不需要停机。
  - `restore <path>`：只能在服务停止时执行；先校验文件（`PRAGMA integrity_check`、迁移版本一致），再原子替换目标库（先写临时文件，再改名），旧库保留为 `.bak`。
- 不做：定时备份、远程存储、增量备份、Web UI。

## 验收标准

- 测试：
  - 备份后修改数据，恢复后数据回到备份时的状态；
  - 损坏文件或迁移版本不一致时，恢复被拒绝，目标库不变；
  - 服务运行中执行恢复被拒绝；
  - 在有写入的同时备份，得到的文件一致。
- README 写明备份/恢复步骤。CI 绿。

## 性能考虑

在 100 万 GL 行的库上，备份期间热读 p95 仍 ≤ 1s（在 Bench 中手动测一次，结果写进 PR）；备份不长时间持有写锁。
