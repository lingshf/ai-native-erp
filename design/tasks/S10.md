## 目标

- **产品**：发票列表能按伙伴、方向、记账日期筛选（TINV-05）。S9 让发票能追溯到订单，但发票列表仍只能从最新往下翻：要看某个伙伴的发票或某个月的发票，只能逐页加载后肉眼找（`tradeInvoiceListQuerySchema` 只有 `company` / `limit` / `cursor`，`packages/core/src/contracts/trade-documents.ts:451–458`）。订单列表在 S7 已有同类筛选（TORD-05），本任务沿用其口径。**一个迁移（018，只加一条索引），不改过账。**
- **技术**：拆出最小常驻闸门，入口块回到 PG-05 预算内（GATE-01，S9 评审遗留 1 / D284）；删除冗余的 `min-width: 8ch`，先证明像素不变再删（CSS-02，遗留 2 / D295）。两项都不改功能。
- **流程**：S9 回顾 7 条行动项落地（下表“回顾行动项落点”）。行动 1、2、7 与行动 3、4、5 在路线图 §5 的部分由本 PR 写入；行动 3–6 在 Demo 模板与发布清单的部分由 PROC-07（版本管理）完成。
- **遗留**：v0.10.0 Demo 补销售方向截图（D302），验收见下“DEMO-10”。

## 不在本 Sprint

- `package.json` / lock 变化。

### 不合并结案与门禁解锁

本节说明各门禁里“结案”的含义，以及任务停下后如何放行后续任务。

1. **结案的两种方式**：
   - **(a) 合并**：PR 合并，且覆盖其合并提交的 main Full 绿。
   - **(b) 不合并结案**：任务书写明的停止条件触发，开发者停下并附证据报告设计角色。证据：CSS-02 为配对图与像素差日志；GATE-01 为 PG-05 字节表。协调者以决定编号确认结果；已开的 PR 不合并关闭；设计角色在任务表把状态写为“结案（不合并，D…）”，并更新下文遗留表。main 没有变化，不需要 Full。
2. **CSS-02 保留规则**属于 (b)。发布说明不提 CSS-02。
3. **GATE-01 未达 75 B**：协调者二选一（GATE-01 决定 4）：
   - ① 接受较小的减少，按 (a) 合并；
   - ② 关闭，属于 (b)，S9 遗留 1 维持到后续 Sprint。
4. **`trade-gui-scenario.ts` 门禁**在 GATE-01 结案时解除：
   - (a)：GATE-01 合并且 main Full 绿时解除；
   - (b)：协调者发布结案决定时解除。即使 GATE-01 的分支改过该文件，未合并的改动不进 main，TINV-05 基于 main 修改。
   - GATE-01 以后若重开，排在 TINV-05 之后，基于其合并后的 main 重做。
   - GATE-01 先做拆分与字节、sourcemap 测量，达标（或协调者接受较小减少）后才改该文件，以免停下的任务占住门禁。
5. **TINV-05 的停止条件**（p95 超预算等）是“停下等设计修正后继续”，不走 (b)。若协调者决定把它移出 S10，另以决定编号调整 CSS-02 的依赖与 DEMO-10 验收 3。
6. **DEMO-10 门禁**：
   - TINV-05、GATE-01、CSS-02 各自已按 (a) 或 (b) 结案；
   - PROC-07 已合并（它没有停止条件）；
   - 覆盖最后一个合并提交的 main Full 绿。
   - 以 (b) 结案的任务不进 Demo 和发布说明。
