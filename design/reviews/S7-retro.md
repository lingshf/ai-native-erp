## 议题 1：独占时段被外部进程打断（D216 / D217）

- **观察**（[#159 正文“时段 1”](https://github.com/lingshf/ai-native-erp/pull/159)）：
  - D216 批给 UI-11e 整机独占时段。precheck 第 6 次采到外部 Vitest（PID 72788，`vitest run packages/infra/test/tooling`），计数归零重来，之后连续 6 次为 0，开跑。
  - 18:07:49 开始 head 对 base 取证；18:12:00 采样器发现 CI-01 worktree（lingshf-refactored-waffle）的 Vitest（PID 41872 / 77932，同类命令 `vitest run packages/infra/test/tooling`）与 biome，按规则于 18:12:02 中止。完成 64 / 165 张（全部 PASS），control、E2E、Vitest 未运行。
  - 协调者确认干扰来自 CI-01 会话、责任在协调侧；D217 通知 CI-01 停用本机 vitest、biome、构建，待其回复“已停”后才批时段 2。时段 2 从头一次跑完，时段 1 日志保留。
  - 代价：一次完整时段（约 7 分钟）作废，UI-11e 合并推迟。
- **根因（推断）**：
  - 独占时段只靠申请方的 precheck 和运行中采样“发现”干扰，没有在批时段之前让其他会话停止本机测试。precheck 与运行期先后采到同类命令（不同 PID），“连续 6 次为 0”只说明那一刻没有外部进程，不能保证之后不再启动。
  - 其他会话不知道时段何时开始；“本机验证一律交给 PR CI”只在出事后（D217）才下达。
- **改进动作**：
  - 批时段前，协调者先向所有在岗会话下达“停用本机 vitest / biome / playwright / 浏览器 / 构建”，收齐“已停”回复后再批；时段释放后再统一解除（负责人：协调者；落点：[路线图 §5“E2E 独占时段”（D115）](../roadmap.md#5-团队流程)）。
  - precheck 期间若采到外部计数进程，申请方报告其来源 worktree，由协调者先处理，再重新计数，不自行等待其消失（负责人：开发 / 版本管理，协调者执行；落点：路线图 §5）。

## 议题 2：Demo 时段 1 因脚本缺陷中止（D227 / D228）

- **观察**（来源是 [run-through](../../docs/demo/v0.7.0/run-through.md) 里当时汇报的摘要；时段 1 的原始终端输出未保存，与议题 1 有 #159 原始日志不同）：
  - `seed-trade` 完成；`seed-orders.mjs`（`27de52e`）写入 PO-F1、PO-F2 后，用采购商品 EXPENSE 建销售单 SO-F3，服务端返回 `400 api.error.tradeDocument.product`，脚本中止。capture 未执行，`finally` 清理干净，未重试。
  - 时段前跑了替身，但其中 `seed-orders` 只模拟退出码，**没有验证该 seed 的实际写入内容**。模板第 9 条要求 seed、capture、清理都由替身覆盖成功与失败分支，这一要求**未满足**。
  - D228 修复：先建服务类商品 SERVICE；新增 `seed-orders-stub.mjs`（按产品规则拒绝无收入科目的商品，对旧脚本退出 1）；再做一次无浏览器的真实服务演练（4 张订单均 201），然后才申请时段 2，一次成功。
  - 评审后（D230）又修订了脚本（第二个 seed 前补归属检查、截图暂存目录每轮唯一），修订版只经过替身验证。
- **根因（推断）**：
  - 替身覆盖的是“编排”（端口、归属、复制、清理），不覆盖“写入的业务内容是否被产品接受”；Demo 数据的业务规则（销售行需要收入科目）没有在脚本编写时对照产品校验。
  - 真实服务演练（D228 那一步）不在模板要求内，是出事后补的。
- **改进动作**：
  - 替身必须执行真实运行会调用的**每一个写入脚本**（seed、capture 的请求部分），并按产品规则断言请求内容；不能只模拟编排（负责人：版本管理；落点：[docs/demo/TEMPLATE.md](../../docs/demo/TEMPLATE.md)“替身验证”）。
  - 申请浏览器时段前，先做一次无浏览器的真实服务演练（迁移 → 启动 → 全部 seed → 就绪清单 → 清理），通过后再申请；演练命令与输出摘要写进 run-through（负责人：版本管理；落点：docs/demo/TEMPLATE.md）。

## 议题 3：文档 PR 多轮评审

- **观察**（`gh` 评审记录，含 `VERDICT: CHANGES_REQUESTED` 的条数，近似）：
  - 文档 PR 5 个被打回共 7 轮：#155 1 轮、#156 2、#163 1、#164 2、#165 1；#160、#162 一次通过。代码 PR：#157 2 轮、#161 1、#159 0。
  - 打回原因归为三类：

  | 类 | PR / 轮 | 评审指出的问题 |
  | --- | --- | --- |
  | A. 文档里的可执行代码，负例未跑 | #156 ×2、#164 ×2 | 哈希快照漏隐藏文件、读取失败不中止、删光文件报“未变”、抛错后跳过后置哈希；第二个 seed 前缺归属检查、递归删除共享目录；预检命令含字面 `\n` 不可复制 |
  | B. 结论超出证据边界 | #163、#165 | 提交计数未绑定 SHA；未区分既有验收与本轮未复测；D204 初稿写“Full 观察不与空载数据直接比较”，把 #147 的伴随采样负载数据（62–65 / 79–82 s）误称为空载（见 [#165 评审](https://github.com/lingshf/ai-native-erp/pull/165#pullrequestreview-6007890268)）；像素“逐字节相同”未限定在对齐区域；“未演示分支都有测试”未逐项举证 |
  | C. 规则缺口 | #155 | 泳道漏写两任务共享的权重文件，允许并行到评审前才 rebase |

  - #165 是本角色自己的 PR：D204 的数据性质在 CI-01 任务书（本角色所写）里已写明“不是空载数据”，初稿转述时仍写错了；另外在 #165 修订中自查到两处测试行号引用错误。
- **根因（推断）**：
  - A 类：S5 行动项 10（复制命令要用替身跑成功和失败分支）已在清单中，但作者跑的负例是“自己想到的”，没有覆盖评审用临时夹具复现的边界（隐藏文件、空集、抛错路径、字面转义）。
  - B 类：汇总性文档（RC 说明、Sprint 评审）转述下游 PR 结论时，丢掉了原 PR 或任务书里的限定语；覆盖率类断言凭印象写，没有逐项引用文件与行号。
  - C 类：计划阶段按“冲突域”列文件，但没有专门列出跨任务共享的单个文件。
- **改进动作**：
  - 含可执行代码的文档，请求评审前用替身跑一组**固定负例**：空目录、隐藏文件、不可读文件、中途抛错、端口 / 归属变化、文本中的字面转义（复制到新终端执行一次）；结果写进 PR 正文（负责人：版本管理、设计；落点：[docs/release/README.md](../../docs/release/README.md) 发布 PR 清单、docs/demo/TEMPLATE.md）。
  - 汇总文档转述测量或证据结论时，**原样带上来源处的限定语**（“只限这批数据”“不与 X 比较”“推断，未验证”），并链接来源；“有测试覆盖”类断言逐项给出 `文件:行`，找不到就写“未找到直接用例”（负责人：设计（Sprint 评审 / 回顾）、版本管理（RC / 发布说明）；落点：docs/release/README.md 清单、本文所在 `design/reviews/` 的后续评审）。
  - Sprint 计划的泳道表增加“共享单文件”一列（例如 `scripts/test-shard-weights.json`、`migrations.ts`），对每个共享文件写明先后顺序与门禁（负责人：设计；落点：[design/tasks/README.md](../tasks/README.md) 下一 Sprint 计划节）。
