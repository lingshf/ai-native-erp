## 议题 1：范围与排他措辞写过了证据（#443、#447、#450、#455、#454）

**发生了什么（观察）**

5 次打回的原文都是一句范围或排他的断言，比证据说得多：

| PR | 原文断言 | 实际情况 |
| --- | --- | --- |
| #443 | “唯一例外” | 该 run 记为 `failed` 并回滚，不是例外 |
| #447 | “v0.3.0 起各版 Demo 只链接到这里” | 只有 v0.2.0、v0.3.0 两份 Demo README 链接该页 |
| #450 | KGAP-16“只补夹具”即可完成 | 没有受支持的 CLI 输入路径 |
| #455 | 托管在 Vanta 所以不算官方 | 它是 GitHub 官方链接的 Trust Center |
| #454 | `legacy-snapshot.md` 已 QA | QA 只到 S26 Windows 正常路径，负例不算 |

这 5 次中，#454 归入“覆盖范围超出证据”一类，其余 4 次归入“事实不准”。#442 第 2 轮的情况类似：预期按文档推断，没有对照代码的实际出口（非零退出加 `INVALID_INPUT`，不是 `blocked`）。

**根因（推断）**

- “只”“唯一”“各版”“不是官方”这类词，要穷举全部实例或拿到反证才能成立。作者只看了支持它的那一处，没有列出全部实例。
- 计划中的预期按文档文字推断，没有沿代码路径确认可达。S27 行动 1 只约束派发消息，没有覆盖作者自己写下的这类措辞。

**改进**：行动 1、行动 2。
