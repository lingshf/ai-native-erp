# AI Native ERP

产品目标是覆盖完整ERP场景，优先实现小企业易用、可追溯的主流程；教学是可关闭辅助，不改变会计正确性。UI与素材保持原创，性能从设计开始，热读p95目标≤1秒、≤100行预览/确认各p95目标≤2秒，不把目标当作已达标声明。完整准则见[产品准则](design/product-guidelines.md)。

当前路线只做SQLite、本机单用户、loopback无登录；PostgreSQL、Docker、登录和权限已延后。按任务逐步调整技术栈并迁移统一账模型，当前计划以[路线图](design/roadmap.md)和[任务总表](design/tasks/README.md)为准；下文旧阶段编号与验收计数仅描述历史，不是当前实施计划。

本质是ERP财务工作台，同时提供可关闭的会计教学辅助。当前本机单人总账支持日记账 → 过账 → 总账 → 试算与调整 → 报表 → 关账；不把尚未开发的应付、应收、库存等模块宣称可用。
使用通用权责发生制和复式记账，现有示例账套金额仍为“教学单位”。当前为非生产演示版，不承诺符合某国会计准则；关闭教学不会改变金额口径或升级为生产财务系统。
当前包含自定义科目及正常方向/备抵解释、基础行维度、显式科目维度结构与确定性现金服务事件闭环；首阶段有限收口标准及完整目标状态见 `design\project.md`。

## 在另一台机器继续开发

使用本轮已验证的Node.js 26.13.0与npm 11；其他版本未在本轮亲验，引擎约束见package.json。克隆公开仓库后，在新的副本中执行：

```powershell
git clone https://github.com/lingshf/ai-native-erp.git
Set-Location ai-native-erp
npm ci
npm test
npm run check
npm start
```

仓库不包含`.env`、原账套、依赖目录或任何登录凭据。npm 11按根`package.json`的`allowScripts`仅放行`better-sqlite3`安装脚本，`koffi`脚本保持禁用，不全局开放生命周期脚本。首次启动会在新副本创建独立的本机教学账套；已有账套不会从其他机器自动迁移。未配置AI时仍可使用确定性手工记账。需要AI时参照`.env.example`及下文受支持的官方Copilot登录/配置方式；新机器必须独立认证并核实模型可用性，原宿主的认证不随代码迁移。

依赖声明均为精确版本，根`.npmrc`以`save-exact=true`保持新增依赖的版本格式；Node引擎与CI统一为`26.x`。Dependabot每周检查npm升级，按React、Vite/Vitest、types及其它开发依赖分组次要/补丁更新，主版本单独提PR，同时最多打开3个版本升级PR；Actions每月检查并合为一组，同时最多打开1个版本升级PR。这些是并发上限，不是周/月累计配额；升级PR同样先评审、CI通过后再合并，不自动合并。

更新依赖前确认`npm config get registry`为`https://registry.npmjs.org/`；本机镜像配置可能写入不可移植的lockfile地址，不能提交私有源配置或凭据。CI轻量检查会拒绝非公共npm源的tarball地址，本地workspace链接不属于tarball。

### M0-08：独立新目标库的主数据

先显式迁移一个新的本机文件，再把其**绝对路径**交给组合根；不要选择原账或快照：

```powershell
npm run storage:admin -- migrate --provider sqlite --file new-target.sqlite
$env:ERP_SQLITE_FILE = (Resolve-Path .\new-target.sqlite).Path
npm run build
npm run start:local
```

启动只校验最新 schema，不自动迁移；旧的 001/002/003 目标库也须先显式运行 migrate 升级到 004，已发布 SQL/checksum 保持不变。首次连接有效目标库时，在固定 LOCAL tenant/book 下建立 DEFAULT 月度教学公司（CNY、精度 2、当前财年）、旧 Book 对应的八科目和 12 个开放期间；重复启动不覆盖已有主数据，不创建凭证。未设置 ERP_SQLITE_FILE 的启动与快照 CLI 仍不打开业务库。已配置时 health 返回 `data:configured`。

左侧“基础配置 → 科目表”提供公司选择、科目新建/编辑/停用；教学公司的内置八科目保持不可修改。统驭模块必须显式选择，不默认推断为 AP。中英、红绿、教学切换不清空编辑器。写入用 revision CAS，版本冲突返回 409 并保留输入，要求显式重新载入；可修正的科目规则校验返回 400 和安全的 fieldErrors，在对应字段说明如何修正，保留草稿且不提示无效重载。列表每次取 100 行，可继续加载；超过 100 行启用 TanStack Virtual。`/api/v1/companies`（GET/POST）、`/accounts`（GET/POST/PUT）、`/periods`（GET/PUT）使用有界游标分页；科目历史可用 `GET /api/v1/accounts/1500?company=DEFAULT&at=2026-01-02T12%3A00%3A00.000Z` 查询。期间冻结可重开，关闭须明确确认且不可重开；有业务活动后的结账流程留待 M0-11。公司创建/期间管理界面仍未提供；凭证界面见下文 M0-10。

“基础配置 → 财务维度”维护维度、有效值、科目结构（必填/可选/禁止）、默认、派生和平衡配置，支持启停及有效期。列表按公司隔离，每页100项，维度值按所属维度过滤，超过100项虚拟滚动。`/api/v1/dimensions` 的 GET 使用 company、kind、dimension（仅 value）、limit、cursor；POST/PUT 接受严格的 `{company, config}`，revision=0 新建，否则 CAS 更新；每次成功写入同事务追加不可变历史。

**D5：允许组合统一采用 Enterprise 的 subset 口径，没有模式开关**：只约束组合列出的维度，未列出不限制；必填/禁止/固定值仍独立校验。相对旧 Book exact，组合没填的可选段现在代表不限制该段。例如组合只列 DEPT=A、COST 为可选，行上额外填写任意有效 COST 值也可匹配；行上 COST 留空仍可匹配。这是统一规则的有意放宽，不是双轨兼容；不提供旧账转换/导入工具。配置保存检查引用存在；应用规则时才检查维度/值的启停和包含端点的有效期，便于先配置未来生效的规则。禁止段连显式 null 键也须移除。默认按账套→科目→主数据→抬头→显式行值覆盖，再按依赖顺序派生，fill 保留显式 null，最后稳定条件固定值并校验结构。平衡纯函数先要求业务借贷相等，再输出精确整数的内部清算候选；M0-09 切片仅输出候选，凭证调用、清算行重校验及来源链路已由下述 M0-10 接通。

### M0-10：凭证草稿、预览与明确确认

“凭证”页只写上述独立新目标库。草稿可保存不完整输入、修改或明确删除，revision CAS 冲突保留输入；记账日期必须显式填写。业务行 Enter 移到下一行、末行 Enter/末字段 Tab 新增，Ctrl+Enter 先保存再预览。预览不写 GL/回执/审计，展示实际维度、来源解释、内部平衡与历史镜像；必须另外点击“确认过账”。确认结果不确定时保留同一幂等键及计划，只允许明确同键重试，不自动再次记账。语言/主题/教学切换不清空编辑内容。

`/api/v1/journals` 按 company、status=draft|posted、limit、cursor 分页；`/drafts` POST、`/drafts/:id` GET/PUT/DELETE 提供草稿维护；`/preview`、`/confirm` POST 使用草稿版本及指纹，确认另须 `confirmation:POST`。`/reverse`、`/replace`、`/reclassify` 仅创建纠错草稿，仍须预览和明确确认；`/:id` GET 返回不可修改的已过账凭证与全部纠错链。业务草稿最多 500 行，列表每页 100 项，超过 100 项虚拟滚动。确认在同一 SQLite 写事务内重读当前同公司科目/期间/维度、重算指纹、校验全部生成行并原子写凭证/回执/审计、删除草稿；同键同内容返回持久原回执，公司内来源引用唯一。

**D6：历史反向行逐项精确镜像同公司原已过账行**，即使原科目已停用/禁止手工或原维度值已失效；不重跑默认/派生。仍检查原凭证、同公司科目、金额正好取反、镜像证据及不能重复冲回。新业务/自动清算行均按当前启用、用途及维度结构校验。替换原子生成反向和新凭证；重分类必须全额，合并展示原反向与新分配，仅允许再全额冲回；纠错日期不能早于原凭证及其任何后代。金额以精确最小单位计算，单项/凭证/公司累计借贷金额均不能超过安全整数范围；公司累计值保存在不可变封存记录，通过索引读取末值，不逐次扫描全 GL。

004 复用已发布 001 的 `receipts` 与 `audit`，为新凭证增加来源/幂等唯一索引，`audit_log` 是同一真实审计存储的只读投影，不写两份审计。完整目标库新 GL 报表留 M0-12；业务事件/过账规则及后续结账留 M0-11，不提供旧账转换/导入。`npm run bench` 另测 100 行 × 3 维度的真实 loopback HTTP（含客户端响应/契约解析，确认包含事务提交），输出 p95/p99 及事件循环延迟；当前仅独立小库，**不等于已通过百万 GL 容量验收**，须等 M0-12 合成生成器。

需要真实只读报表时，先构建，再显式选择**独立的M00已验证快照目录**，不能传活动账套的`data`目录：

```powershell
npm run build
$snapshotDir = Read-Host 'M00 verified snapshot directory'
npm run preview:legacy -- --snapshot-dir "$snapshotDir"
```

成功启动不打印就绪行；打开`http://127.0.0.1:4180`，或检查同源`/api/v1/legacy/context`返回200及所选快照身份确认就绪。源无效、档案/地址不符或端口占用明确失败，关闭时先停API再关reader。此CLI只读取`ERP_PROFILE/ERP_HOST/ERP_PORT`，不读取旧`.env`、`HOST/PORT/DATA_DIR`；仅Local和字面loopback，拒绝4173、非规范端口和未实现认证的Server，不从环境选择账套。

财务页使用HashRouter，只有一个来自快照的期间选择，初次默认最后可用期间/调整后试算。三阶段切换不重新请求；科目下钻包含同月全部调整、冲销与结转，不带stage过滤。总计不随分页变化，按行ID而非凭证ID保留多行；超过100行可明确加载下一页。来源变更409须点击“重新加载快照”，清旧缓存/游标并读取新context后才采用新来源最后期间；可保留原总账科目路由，不自动切账。错误不自动重试，提供显式操作。金额按`scale:2`精确显示，不猜币种或翻译原名称/摘要/维度。

开发时API固定4180、Vite固定5173/strictPort。在第二终端运行`npm run dev --workspace @erp/web`；普通同源GET无Origin也可代理，无需额外许可。确实带`Origin:http://127.0.0.1:5173`的请求，只有API启动时另加`--dev-origin http://127.0.0.1:5173`才允许。API与Vite均不提供跨域CORS响应，Vite拒绝外域Host，不设`allowedHosts:true`。改API端口须显式同步并验证代理目标，不能扩大来源许可掩盖错配；开发origin不是认证，不开放LAN。

工程只有三个workspace：`@erp/core`（domain/application/contracts）、`@erp/infra`（storage/http/legacy及组合根）、`@erp/web`（React及`src/ui`的labels/偏好），没有`apps/`。包导出直指`.ts`，相对TS导入使用`.ts`/`.tsx`；`npm run typecheck`一次覆盖源码和TS测试，不输出JS。目录边界禁止core反向导入infra、domain导入application、web导入Node或存储驱动。Zod是DTO单一来源；需要OpenAPI文件时显式执行`npm run openapi -- openapi.json`，不挂测试前置构建。偏好仍保存于同源`erp.workspace.preferences.v1`，默认中文/红色/教学关闭，不改旧偏好键。凭证/GL 仅在独立新目标库写入；认证、业务事件及原账切换仍待后续阶段。

`npm test`运行根Vitest的core/infra（Node独立进程）及web（jsdom）项目；`npm run test:changed`只运行相对`origin/main`受影响的测试。旧`tests/*.test.mjs`单独用`npm run test:legacy`运行，完整验证使用`npm run verify`。`npm run check`使用Biome recommended lint与formatter覆盖`packages/`、`scripts/`，不再维护`node --check`列表。旧`src/`、`public/`、`tests/`不改文件、不检查格式或lint规则；其override保持linter解析引擎启用但`preset:none`，避免完全禁用引擎时跳过语法解析，这个过渡配置在M0-15随旧代码移除。边界解析仍用Babel：当前TypeScript 7仅导出版本信息，没有所需AST API；`acorn`仍被旧labels测试实际消费。

PR CI限时10分钟：安装、Biome、类型和边界检查后，对实际PR base运行受影响Vitest；任意workspace的`package.json`/lock、Vitest或`tsconfig*`改动回退全部非慢测试。只有旧`src/`、`public/`、`tests/`改动才运行旧套件（M0-15删除此分支）。`*.slow.test.ts`/`*.slow.test.tsx`不进入PR或`test:changed`，只进入完整运行；本地`npm test`/`verify`仍是完整模式。CI/Full的summary合并Vitest与实际执行的旧套件，列出最慢10个测试。

### M02只读快照CLI（M02已验收发布）

### M02目标存储工具（M02已验收发布）

新目标与旧账格式不同；[14节点边界图](design/diagrams/m02-storage.svg)区分目标存储与快照只读路径。仅对显式选择的独立本机文件使用以下命令，父目录须已存在。构造/普通启动不隐式迁移，工具不从`.env`、`DATA_DIR`或旧账选择目标，不导入业务数据：

```powershell
npm run storage:admin -- --help
npm run storage:admin -- migrate --provider sqlite --file new-target.sqlite
npm run storage:admin -- verify --provider sqlite --file new-target.sqlite
npm run storage:admin -- provision --provider sqlite --file new-target.sqlite --tenant T1 --book B1 --company C1
```

### ERP一致快照与独立恢复

在项目根目录执行，目标必须是**不存在的新文件**，父目录需已存在：

```powershell
New-Item -ItemType Directory -Path backups -Force | Out-Null
node scripts\enterprise-backup.mjs backup --source data\erp.sqlite --target backups\erp-snapshot.sqlite
node scripts\enterprise-backup.mjs restore --source backups\erp-snapshot.sqlite --target backups\erp-restored.sqlite
```

backup和restore都通过只读源连接及SQLite `VACUUM INTO`生成一致快照；先核内核完整性再独占创建目标，成功才输出SHA256、字节和快照本身的完整性/计数摘要，不输出财务明细或token。源可处于WAL使用中；并发后续写入不会混进本次快照摘要。已有文件（即使空）、同一路径、非ERP/坏库或不平衡账拒绝；竞争者中途创建目标也不覆盖。失败返回非零，不能把失败遗留文件认定为有效备份。

restore只创建并校验**独立副本**，不会替换活动账本或切换当前服务。已接受来源的原回执/token可在恢复副本重试；只在内存中的未完成preview token不可迁移，必须重新预览。恢复测试核对原金额、维度、来源回执和零重复入账；完整性通过不等于发现所有“平衡但错”的业务，更不是生产灾备、加密、自动备份或跨版本迁移保证。新机器AI认证也不随账本迁移。备份包含账务数据，应由操作者妥善保护，不提交到公开仓库。

“科目配置”中选择自定义科目的“配置”，在独立“会计属性”表单选择正常余额借/贷方向、一般/备抵用途和关联原值科目，明确确认后保存。属性版本独立于启停/录入权限版本；冲突须刷新核对，失败保留输入。内置八科目的身份、类型、状态和默认正常方向仍受保护。

资产/费用默认借方，负债/权益/收入默认贷方。**正常方向不是只能借或只能贷的限制**；合法的退回、冲销、备抵反向余额仍可保存和过账。直接记账控制继续用原“禁止手工 / AI 录入”，没有重复新增“控制科目”开关，也不声称有应收应付子账。

备抵须采用与类型相反的正常方向，关联同类型、一般用途且类型正常方向的原值科目；可以关联停用原值以解释历史。多个备抵可以关联同一原值，不能形成链/环；已有备抵关联的原值不能改为备抵或反向正常方向。只有一般/备抵两种有实际行为的用途，没有自动清账、在途单据核销或暂记负责人流程。

“试算与报表”新增余额信号与原值/备抵/净额解释。例如自建1500资产原值100.00、1510备抵贷方10.00，关联后显示100.00 / -10.00 / 90.00；原资产报表已含备抵，不会再扣一次。余额信号显示实际期末借减贷和按正常方向计量金额，反向仅提示。资产负债类组合用期末余额；收入/费用组合用本期非结转发生额，月结后仍显示历史收入/折扣，而单科目期末余额为零。这里的金额是独立虚构教学示例。

历史查询按**当前属性**解释，不是交易发生时的属性快照；改属性不改原分录、类型、报表合计或旧月度结转。原业务回执保持不变，但任何属性保存（即使同值/改回）会使未完成业务预览失效，必须重新预览。旧账只新增空属性表，未配置时按类型默认；不回填历史。AI获得相同属性与解释，但无配置/自动过账权限。

## 旧教学账：基础行维度（FG-02部分）

“维度配置”创建部门/成本中心等维度及有效值，编号/名称创建后不可改、不可删，状态可启停并按版本校验。维度编号为1-20位大写字母/数字/下划线且以字母开头；值编号另可用短横线。每张凭证的每一行可选最多10个维度值，留空就是未分配，不自动默认或派生。不需要为每个部门复制费用科目。

保存、过账及AI建议返回时都校验已填写的维度和值是否存在并启用。停用不改写或隐藏历史；旧草稿须改用有效值、重新启用或删除后再处理。精确系统冲销保留原行维度，即使维度随后停用仍可纠错；原已过账行维度不可编辑。

日记账/AI建议显示行维度，“总账”可按一个维度/值筛选，停用值仍可查历史。**这不是独立平衡的维度试算/报表**：现有月度教学结转仍汇总为未分配行，不把损益按维度归零，筛选后的期初会继续累积原匹配行。未筛选报表与八科目/月结语义不变。必填/精确组合结构见下一节；尚无默认/派生/固定值、有效期、平衡维度或分维度结转，FG-02不算整体完成。

AI会收到维度名称和有效值。仅在输入明确写出 `DEPT=OPS` 等已有编号对时才能建议该维度；服务端检查，AI不自行推断，也不保存配置或凭证。维度建议仍需逐行核对，再保存草稿及另行确认过账。不要在维度名称中填敏感信息。旧账只新增空维度表，不回填旧凭证；已有维度交易后不建议退回忽略维度的旧程序。

## 旧教学账：科目维度必填与允许组合（FG-02部分）

在“维度配置”下方选择**单个精确科目**，为已有维度设置“不约束 / 可选 / 必填”，编辑允许组合JSON数组并显式选择启用，确认保存。每科目最多一份结构（1-10段、最多50组），不会发生区间重叠。无配置或未启用不约束新录入；其他未列维度仍可填写，仍须通过原有效值校验。启用时须引用当前启用的维度/值。停用已有维度后可明确停用其结构，不会自动改配置。

例如先创建DEPT=OPS/SALES、COST=C1/C2，在4000收入科目设置DEPT必填、COST可选，允许组合填：

```json
[{"DEPT":"OPS","COST":"C1"},{"DEPT":"SALES"}]
```

OPS+C1、SALES且COST未填可以；OPS+C2、OPS未填COST或缺DEPT均拒绝。**省略可选段表示只能为空，不是任意值。** `[]`表示不限制组合，但保留必填检查；`{}`只可作为全段可选结构中的“全空”组合。空字符串/null不是空段，应省略键。不使用源ERP区间/通配符/高级表达式语法，不会自动默认、派生或覆盖输入。

同一约束覆盖手工普通/调整凭证保存、已有草稿实际过账、现金服务业务预览/确认、AI返回后的建议。错误定位行/科目/结构版本；失败不修改草稿或余额。旧凭证/账套配置不回填，旧草稿可纠正或删除；精确系统冲销先核对来源后豁免新结构，月度教学结转仍汇总未分配。历史查询不按当前结构过滤。若现金和收入科目结构互相矛盾，现金服务同一维度图不能同时满足两行，必须修改配置，不自动改业务维度。

结构保存按版本防覆盖；启停/同值保存/改变后改回也使旧业务预览失效。事件预览与原始回执显示当时适用的完整启用结构/版本，不受后续配置改写。历史旧回执没有结构字段仍可查看。AI上下文包含结构，但必填值也须在输入中明确写 `DEPT=OPS COST=C1` 等合法编号对，AI不自行补值或过账。启用结构后不要退回忽略该控制的旧程序。

## 旧教学账：确定性现金服务业务（FG-04/05部分）

“教学业务”维护服务编号/名称/服务组，再创建贷方收入科目规则：**具体服务 > 服务组 > 全部**。全部匹配写 `*`；组须属于已有服务。服务编号/名称不可改，组/状态可按版本修改；规则支持按版本修改范围、匹配、科目、状态。无匹配或最高级有多个启用规则均拒绝，受限命中科目也拒绝，绝不回落到较低级规则。借方固定1000现金；这条教学GL路线仍遵守科目启用/允许手工录入限制，不代表已经实现子账控制科目。

例如创建服务 `SVC`、组 `GENERAL`、全部规则 `* → 4000`，输入新来源号 `CASH-001`、开放期间日期和金额 `10.00`（虚构教学数据，非源综合案例金额）。点击“预览确定性分录”只显示命中规则/版本、候选优先级和借现金/贷收入各10.00，不保存、不改变余额。可选维度原样复制两行。再点“确认生成并过账”并明确确认，才同步生成一张已过账普通凭证及不可变来源回执；不会经过可编辑草稿，也不会调用AI。

预览和过账共用一个确定性计算逻辑。输入变更、任何服务/规则/科目/维度/期间配置变化（含改变后改回）、或服务重启均要求重新预览；采用保守的全局配置检查，无关配置变化也失效。金额相同的 `10`/`10.00` 和空维度/未提供维度按同一输入处理。日期仍须属于现有开放期间，不建立新月份。失败保留输入，不自动换来源号或凭据。

网络失败可使用原输入/来源号和原预览凭据重试，持久回执只返回原凭证；重启、关账或配置停用后仍可返回原已完成结果，不会二次入账。相同来源不同输入/凭据拒绝；已完成来源不可再次预览，查看页面下方原始规则/分录回执及日记账来源关联。GL精确冲销保留回执，**不等于业务取消、不释放来源号**，重新记录必须新编号。未完成预览不持久保存，刷新/保存配置后须重新预览。

旧账只新增空服务/规则/来源表，不补造历史业务来源、不回填规则、不改原八科目/ID3草稿/金额/期间。这里只是“已完成教学服务收到现金”的最小事件适配，不是任意规则编辑器、真实发票/应收/采购/库存/税或完整FG-04/05；没有有效期、多轴匹配、异步会计转移完整性或子账取消。

## 真实 AI 接入

### 当前 Copilot 配置

交付时若目标不存在 `.env`，只创建以下**非密钥**配置；已有 `.env` 原样保留，不复制源工作区的环境文件：

```dotenv
AI_PROVIDER=copilot
AI_MODEL=gpt-6.1-sol
```

使用官方 `@github/copilot-sdk`，不复制聊天凭据、不配置内部端点。SDK 在本次宿主报告已有受支持的**环境认证**，模型目录实际提供 `gpt-6.1-sol`，隔离会话也实际选择该模型；这不等于已证明复用了持久 CLI 登录。
需要启动进程仍具备 SDK 支持的认证；另开终端或宿主凭据失效后不保证可用。隔离模式关闭系统密钥链访问，因此仅登录 CLI 不保证本模式可用。认证失败会明确报错，不自动换模型或伪造回复；不要导出私有 token，也不要把密钥贴进聊天。

Copilot 每次只处理一个请求，独立临时会话没有工具、MCP、技能、仓库指令、文件／执行权限或跨会话记忆。请求前检查实际工具列表为空，并在生成前后核对模型。临时状态放在系统临时目录而非 OneDrive，运行时关闭后删除；清理失败会报错。AI 推理超时 30 秒，关闭运行时可能另有短暂延迟。

Copilot 接入交付时已用虚构账套实际验收讲解（利润 2,000 教学单位）与凭证建议（借现金／贷收入各 10.00），未保存或过账。完整五次真实尝试及其中的质量／校验失败均记录在 [评审证据](design/reviews.md)，不代表模型永远正确。该接入当时26项测试及独立评审通过，保留模型身份核实例外；最新增量验证/评审/预览版本见该文档最上方，不沿用旧记录冒充新验收。

- 自然语言建议只返回待核对的分录与解释。点击“填入编辑器”不保存；须另行保存草稿、确认过账。
- AI 会发送你的输入、演示科目表、维度名称/有效值及科目维度结构、选定期间状态和报表到配置的服务，可能产生费用。教学讲解另含只读关账快照：草稿数量、当前能否关账、开放期间的结转预览，或已关闭期间的实际结转凭证；不会发送草稿内容。预览不含未过账草稿，草稿过账后可能变化；快照仅代表发送时点，不是实时承诺。不要输入真实财务、个人信息或密钥。
- AI 文本可能错误，不是会计权威；账本校验与已过账数据才是事实来源。
