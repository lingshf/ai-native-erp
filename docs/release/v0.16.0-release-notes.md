# AI Native ERP v0.16.0

> **发布候选，尚未发布。** 日期待定，tag 待协调者授权。产品代码基线为 main `35df068`（REFAC-07 [#275](https://github.com/lingshf/ai-native-erp/pull/275)；S17 的三项开发任务全部已合并，该提交的 main Full run 45263713443 绿）。tag 目标按 D484：`release/v0.16.0` 上审核通过的 RC 头（与 v0.14.0、v0.15.0 一致），授权前不打。

本地优先、面向小企业的 AI-native ERP，也可用于会计教学（教学说明可关闭）。SQLite、本机单用户、无登录。**非生产演示版。**

版本号取 minor（0.15.0 → 0.16.0）：TLIST-01 让订单列表与发票列表多一个按钮，是用户可见的小功能。**无迁移（仍为 020），无依赖变化**，已有账套不需要 migrate，不改过账规则与任何金额、数量口径。

## 亮点

- **订单列表与发票列表多一个“刷新列表”按钮**（TLIST-01，[#271](https://github.com/lingshf/ai-native-erp/pull/271)）：在筛选栏“清除”之后（英文 “Refresh list”）。点它按当前已应用的筛选从第一页重新读取；筛选栏里还没点“应用”的输入保留，不改地址与浏览器历史，不弹离开确认，不清录入区草稿。此前只能再点一次“应用”（会顺带应用没应用的输入）或刷新整页。凭证列表早有同名按钮（JV-FIX-01）。
- **预付 / 贷项 / 纠错页内部拆分**（REFAC-07，[#275](https://github.com/lingshf/ai-native-erp/pull/275)）：`ActionEntry` 由 643 行减到 73 行，只搬移，界面与行为不变。
- **测试支撑代码拆分**（REFAC-08，[#270](https://github.com/lingshf/ai-native-erp/pull/270)）：`tradeGuiSmoke` 的 `smoke.ts` 由 262 行减到 97 行，不改断言。无用户可见变化。

## 需要注意

- **无需 migrate。** v0.15.0 的账套（迁移 020）可直接使用。
- **没有体积数字。** #271、#275、#270 的正文都没有构建体积测量，本版本不给体积数字（按 #253 的规则，不自己重测、不估算）。
- **证据口径**：REFAC-07 的“行为不变”靠 #275 的 R4 逐步等价（16 个场景，base 与 head 逐字节相同）；REFAC-08 的“断言不变”靠 #270 的 T2（11 条断言调用链，仅 `pending` 读取方式不同）。两者都是静态或 jsdom 证明，不是真实浏览器；真实 Chrome 下的页面表现见 Demo。
- **推迟：FIX-TADJ-BUSY**（[#276](https://github.com/lingshf/ai-native-erp/pull/276) 任务书）不在 v0.16.0 发布，留到后续版本。
- **真实 Chrome（Demo，R3 时段，端口 4203，退出码 0）**：订单页、发票页的筛选条在中英文 1440 下都是“应用 / 清除 / 刷新列表”三个按钮（类型 submit / button / button）；刷新记录：选 AR 并应用，伙伴框输入 ZZZ 不应用后点刷新，输入框仍是 ZZZ、地址栏 hash 不变、请求只带 side=AR、历史长度 2 → 2（订单页与发票页各一次）；390 宽中文界面三个按钮同一行、都在视口内，页面 scrollWidth 390。产物：`capture-log-real.json`；方法：`capture.mjs` 在真实 Chrome 下记录；来源：[#277](https://github.com/lingshf/ai-native-erp/pull/277)。英文 390 宽没有实测。
- 数字（行数、用例数、场景数）取自各来源 PR 正文，发布前未重测。
