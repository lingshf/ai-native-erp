# AI Native ERP v0.15.0（草稿）

> **草稿，尚未发布。** 未打 tag。产品代码基线为 main `00d1ed4`（REFAC-05b [#265](https://github.com/lingshf/ai-native-erp/pull/265) 的合并提交，S16 的四项开发任务全部已合并；该提交的 main Full run 45247858180 绿）。其后 main 只有文档与工具提交（#266 SLOT-03 只改 `scripts/slot`，不改 `packages/`；#267、#258 为文档）。tag 目标按 D21 / D398 为 RC 与 Demo 合并后的提交，发布前核对 `git diff 00d1ed4 <tag 目标> -- packages` 为空，并如实报告 `scripts` 的差异，经协调者授权后才打 tag。

本地优先、面向小企业的 AI-native ERP，也可用于会计教学（教学说明可关闭）。SQLite、本机单用户、无登录。**非生产演示版。**

版本号取 minor（0.14.0 → 0.15.0）：TORD-08 让订单详情多一列，是用户可见的小功能。**无迁移（仍为 020），无依赖变化**，已有账套不需要 migrate，不改过账规则与任何金额、数量口径。

## 亮点

- **订单详情多一列“贷项冲回数量”**（TORD-08，[#262](https://github.com/lingshf/ai-native-erp/pull/262)）：订单行表在“未开票数量”之后、“单价”之前多了一列，显示该行未作废贷项冲回的数量；没有贷项时显示 `0`，读取中显示“…”。“已开票数量”仍是扣除贷项后的净数，两者不要相加。
  - 例（#262 的 jsdom 用例）：订购 10.5、已开票 6、未开票 4.5、冲回 4。
  - 订单行表最小宽 920 → 1040 px；390 px 宽下仍在表格容器内横向滚动，要向右滚才能看到新列。该宽度的实测记录见 Demo（真实运行前尚无）。
  - 不新增 SQL（#262 的 K4：base 与 head 均为 4 条语句），不改迁移；订单发票读取接口的响应多了 `creditedQuantity` 字段，见下“面向调用方”。
- **订单页内部拆分**（REFAC-05b，[#265](https://github.com/lingshf/ai-native-erp/pull/265)）：`order-workspace.tsx` 由 608 行减到 110 行，只搬移，界面与行为不变。
- **开发流程**（无界面变化）：测试支撑代码的类型错误现在会让 PR CI 失败（CI-03，[#261](https://github.com/lingshf/ai-native-erp/pull/261)）；slot 采样规则 R3 与 `-Ports` 端口检查（SLOT-03，[#266](https://github.com/lingshf/ai-native-erp/pull/266)）。

## 面向调用方（HTTP API、CLI、迁移）

- 迁移：**未变**（仍为 020）；#262 与 #265 均未新增迁移文件。
- API：**响应加了一个必填字段**。`GET /api/v1/trade/orders/{id}/invoicing` 返回的 `invoiced[]` 每行在 `invoicedQuantity` 之外多了 `creditedQuantity`（decimal，格式与 `invoicedQuantity` 相同，没有贷项时为 0）；契约 `tradeOrderInvoicingSchema` 是严格对象，按旧 schema 严格校验响应的调用方需要更新。端点、参数与请求契约未变；不新增 SQL（#262 K4）。依据：`git diff --stat 94aefc2 00d1ed4 -- packages` 的契约改动只有 `packages/core/src/contracts/trade-documents.ts` 的这一行。
- CLI：未变（`94aefc2..00d1ed4` 的 `packages/` 改动文件中没有 CLI 相关路径）。
- 开发工具：`scripts/slot/slot-run.ps1` 新增 `-Ports`（非 `-Stub` 缺省退出码 4、端口被占 7、查询失败 8）和 `tooling head=` 日志行，只影响独占时段的运行器，不影响应用。
