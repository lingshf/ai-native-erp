# AI Native ERP v0.19.0（发布说明草稿）

> 状态：**RC 草稿，未发布**。RC 范围终点固定为完整 SHA `6156759c2aef6b9805aca70ba5505490e2bd4c5b`（MEAS-01 [#298](https://github.com/lingshf/ai-native-erp/pull/298)）；TLIST-04、REFAC-11、MEAS-01 对该终点的 `merge-base --is-ancestor` 退出码均为 0。tag 与发布日在授权后填入（D484）。

本地优先、面向小企业的 AI-native ERP，也可用于会计教学（教学说明可关闭）。SQLite、本机单用户、无登录。**非生产演示版。**

版本号取 minor（0.18.0 → 0.19.0）：TLIST-04 让财务维度页多了一个按钮，是用户可见的小功能。**无迁移，无依赖变化**，已有账套不需要 migrate，不改过账规则与任何金额、数量口径。

## 亮点

- **财务维度页多一个“刷新列表”按钮**（TLIST-04，[#296](https://github.com/lingshf/ai-native-erp/pull/296)）：在“新建配置”之后（英文 “Refresh list”）。点它按当前公司、类型与上级维度从第一页重新读取列表；所选项和正在编辑的内容保留，不弹确认，编辑器打开时仍可用。Tab 顺序多一站。
- **订单详情内部拆分**（REFAC-11，[#299](https://github.com/lingshf/ai-native-erp/pull/299)）：`OrderView` 的函数体拆到 `trade-orders/` 下的新文件，只搬移，界面与行为不变。
- **测量脚本入库**（MEAS-01，[#298](https://github.com/lingshf/ai-native-erp/pull/298)）：`scripts/measure/` 统一包体积测量口径，只影响开发流程。

## 需要注意

- **无需 migrate。** v0.18.0 的账套可直接使用。
- **体积（#296，来源：#296 正文）**：`Dimensions` 路由块 +103 B（上限 +200 B），首屏、其他块与 CSS ±0。
- **体积（#299，来源：#299 正文 R7，`-HASH` 口径）**：订单页块路由 19014 → 19218 B（+204 B，预算 +900 B），首屏 ±0，其他路由 ±0，CSS 不变。
- **证据口径**：REFAC-11 的“行为不变”靠 #299 的 R4（5 个场景逐字节相同），是 jsdom 证明；TLIST-04 的用例同样是 jsdom，不模拟按键。真实 Chrome 的 Demo 证据（财务维度页 1440 / 390 px 与键盘记录、订单详情截图）在窗口运行后补入，见 [Demo](../demo/v0.19.0/README.md)。
- 数字取自各来源 PR 正文；本 RC 的重测结果见 Demo 的 run-through。
