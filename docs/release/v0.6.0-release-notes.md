# AI Native ERP v0.6.0

> **发布候选草稿**：发布日期待定，未获打 tag 授权。产品代码基线为 main `0f74db9`（S6 功能任务全部合并，Full 12/12）；自 v0.5.0（tag 所指提交 `5e222e7`）起 #132–#148 共 17 个提交，其中 #140、#143、#145、#146 是设计提交。按 D21，tag `v0.6.0` 打在发布 PR 合并后的 squash 提交上。完整变更对比：[v0.5.0...v0.6.0](https://github.com/lingshf/ai-native-erp/compare/v0.5.0...v0.6.0)（tag 创建后生效）。

本地优先、面向小企业的 AI-native ERP，也可用于会计教学（教学说明可关闭）。SQLite、本机单用户、无登录。**非生产演示版。**

版本号取 minor（0.5.0 → 0.6.0）：新增订单列表与保存前预览两项用户可见功能和两个新 API，向后兼容，无新增迁移。

## 亮点

- **订单列表**：订单页新增列表，按订单号排序、每页 100 条、可加载更多；点订单号即查看只读详情（#132）。
- **订单保存前预览**：点“预览”由服务端算出每行和整单金额，预览不保存、不占号；改动任何字段即清除预览（#138）。订单页因此与发票页的“先预览再提交”一致。
- **业务事件“待转队列”**：操作列三个按钮完整显示且都能点中（#133）；主数据保存失败后焦点更早回到输入框（#135，DOM 焦点，读屏时序未实测）。
- **迁移核对页（390 宽）**：键值表不再在词中间断开（#148）。
- **标签页图标**：首页不再请求 `/favicon.ico`（#136，真实 Chrome 抓包证实）。
- **D-7 仍只是部分完成**：`styles.css` 又删去一批全局声明（UI-11b/c/d），但订单列表 `button.cell-link` 的圆角还靠全局 `button { border-radius }`，UI-11e（S7 候选）完成后才算完。

## 面向调用方（HTTP API、CLI）

- 新增 `GET /api/v1/trade/orders?company&limit&cursor`（`listTradeOrders`，keyset 分页，走主键）。
- 新增 `POST /api/v1/trade/orders/preview`（`previewTradeOrder`，不保存、与保存金额同源）。
- 既有 `POST /api/v1/trade/orders` 不变；CLI 的参数、输出、退出码不变（FLAKE-04 #144 为部分修复；FLAKE-05 #147 在最终验证中修复前后逐字比对 **11/11 一致**、前后均 0 失败，证据见[验证 gist（固定修订 55f1bc1）](https://gist.github.com/lingshf/d1752c2ae3049930000445f77b623f6c/55f1bc1df52c9c6bda16e7a0cc904a3def2f7873)）；日志、端口、迁移编号、依赖未变。
- 依据：`git diff v0.5.0 origin/main` 中没有迁移与依赖变化；`packages/core/package.json` 只增加 3 条 workspace 内部子路径导出（私有包，D199）。

## 已知限制

- **D-7 仍只是部分完成**（UI-11e，S7 候选）。
- **旧账迁移（M2）仍未完成**：M2-05（演练）与 M2-06（切换）未开始，另需用户授权；迁移核对页只读，核对通过不等于允许切换。
- 订单列表只有排序与分页，没有按伙伴 / 日期 / 方向筛选（需要新索引即为迁移，另行立项）；订单页仅限非库存订单；导入、核对确认与备份 / 恢复仍是命令行。
- B4（过账规则）保存成功 / 取消的焦点路径未经真实 Chrome 验证，只有 jsdom 覆盖（#135）。
- **CLI 冒烟超时预算（D199，#146 / #147）**：3000 ms 是防挂死阈值，未放宽；验收只针对 PR 层实际负载。在整机 CPU 满载（load-cpu）的压力观察下，CLI 冒烟仍会超时，本版不宣称“整机满载下已解决”。
- 上表里的像素差、页面高度、字节数取自各 PR 正文，发布前未重测。
- 本版 Demo 在发布候选合并后另行准备；v0.5.0 的 [Demo](../demo/v0.5.0/README.md) 仍可参考。
