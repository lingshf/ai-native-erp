本地优先、面向小企业的 AI-native ERP，也可用于会计教学（教学说明可关闭）。SQLite、本机单用户、无登录。**非生产演示版。**

版本号取 minor（0.13.1 → 0.14.0）：TINV-09 改变订单的已开票数量与开票状态，是用户可见的功能变化。**有一个迁移（020）**，只重算已保存的开票状态，不改表结构；无依赖变化，不改过账规则。

## 亮点

- **贷项冲减订单的已开票数量**（TINV-09，#250）：订单行的已开票数量 = 未作废发票行数量之和 − 这些发票行上未作废贷项数量之和。
  - 订单详情的已开票 / 未开票数量、订单列表的“开票状态”列和“开票状态”筛选都按新口径。例（#250 用例 V1 的场景；迁移用例 V7 另见下）：订购 10、开票 6、贷项 2 → 已开票 4、未开票 6、部分开票；再贷项 4 → 已开票 0、未开票；取消后一笔贷项 → 回到已开票 4。
  - **被冲回的数量可以再开票**，过账时的订单匹配用同一口径，不会判为超量。
  - 取消贷项会让已开票数量恢复。若此前已对冲回的数量再开过票，取消后已开票数量可能超过订单数量：系统不拒绝取消，状态为“已开完”。
  - 订单页教学说明中英各多一句（关闭教学模式后不显示）。
- **凭证页按钮改名**（JV-FIX-01，#254）：工具栏的“重试”改为“刷新列表”（Retry → Refresh list）。该按钮一直只是重新读取凭证列表，行为不变；账套读取失败时错误提示里的“重试”不变。
- **PR CI 多一步静态预检**（CI-02，#248）：开发流程变化，无界面变化。

## 需要注意

- **升级需 migrate 到 020。** 迁移只重算已保存的开票状态：已开完后又部分贷项的订单由“已开完”变“部分开票”，全部贷项的订单变“未开票”（用例 V7 的 PO-07、PO-08）。此前（v0.13.1 及更早）贷项不改变开票状态，升级后列表的开票状态和按状态筛选的结果可能与升级前不同。
- **体积变化（REFAC-06b，#251）**：期末结账、调整、贸易报表、核销四页不再加载发票页代码。测量对象为各路由“路由新增 JS / CSS”，方法为 D432（文件名哈希屏蔽后的 gzip-9），base `5803ae8` 与 head `69e15a3` 各在 clean worktree 构建，来源为 #251 正文 B4 逐路由表。
  - 期末结账 JS −10287 B、CSS −1246 B；调整 JS −14537 B、CSS −1246 B；贸易报表 JS −10185 B、CSS −1246 B；核销 JS −10286 B、CSS −1246 B。
  - 发票页路由 JS +220 B、CSS ±0（超出任务书 +200 B，按 D462 ① 接受）；其余路由 JS −3 B 至 +4 B（D462 视同噪声）。
  - 首屏入口块 `index.js`（测量对象：入口块文件，不是路由新增）：未压缩 −167 B；文件名哈希屏蔽后的 gzip-9 −82 B（D432 方法，base `5803ae8` 与 head `69e15a3`）；来源为 #251 正文 B4 “首屏与 D462 的解释”一节的入口块条目，与上面的逐路由表分开；D462 ② 接受。
  - 数字取自 #251 正文，发布前未重测；合并基为 `5803ae8`。
  - **REFAC-06c（[#256](https://github.com/lingshf/ai-native-erp/pull/256)，合并提交 `94aefc2`）**：`InvoiceEntry` 拆成 hooks、命令和展示组件，无界面变化。测量对象为发票页路由 `src/TradeInvoices.tsx` 的“路由新增 JS”，方法为 D432（文件名哈希屏蔽后的 gzip-9），merge base `03f129b` 与 head `50ebfa4` 各在 clean worktree 构建，来源为 #256 正文 P7 节的路由表：JS 21006 → 21896 B（**+890 B**，D461 上限 ≤ +900 B）。其余路由的路由新增 JS、首屏入口（`index.html` 闭包，JS 160872 → 160872 B）和 CSS（两侧都有的 12 个文件，屏蔽哈希后内容摘要相同）均为 ±0。这与上面 06b 的 +220 B 是不同 PR、不同基线的两次测量，不相加。数字取自 #256 正文，发布前未重测（D466：不按新 main 重测）。

## 面向调用方（HTTP API、CLI、迁移）

- 迁移：新增 **020**（`020-trade-order-invoicing-credits.sql`，只有说明注释，不建、不删、不改对象）。运行 020 时按新口径重算所有有订单引用发票行的订单的开票状态；019 的回填与 020 共用同一函数，可重复执行。schema 指纹与 019 相同。
- API：端点、参数与契约 schema 未变（TINV-09 任务书“不涉及”：契约 schema；依据是 #250 的改动文件列表不含契约文件）。`GET /api/v1/trade/orders/{id}/invoicing` 与订单列表 `invoicing=` 返回的数值按新口径，这是行为变化，不是接口变化。
- CLI：未变。

## 已知限制

- 同 [v0.13.1](v0.13.1-release-notes.md#已知限制)：旧账迁移（M2）仍未完成，只在虚构夹具上验证。
