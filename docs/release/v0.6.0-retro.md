## 议题 1：Demo 材料里的脚本与实际运行不一致

- **发生了什么**：Demo 跑完后，README 的复跑命令和两个 PS1 经过多轮评审修订（capture 非零退出不复制、seed 后复核端口归属、固定 blob SHA）。修订后的脚本没有真实复跑，只通过无浏览器替身 `stub-check.ps1`（7 个场景）验证；#151 为此打回 4 轮。
- **观察**：首版 Demo 的运行记录漏了 seed 步骤的复核；首次替身运行没有隔离 TEMP，删除了真实的 `$env:TEMP\demo-s6-shots`。已提交的截图不受影响（与 5675c9e 一致），已在 #151 披露。
- **根因（推断）**：脚本是在运行之后才整理成可复制的形式，没有在写入前先按模板（`docs/demo/TEMPLATE.md`）逐条对照；替身一开始就把“会删除目录”的操作指向了真实路径。
- **改进动作**：
  - Demo 开跑前先写好脚本并通过替身验证，再申请时段，真实运行用的就是评审过的脚本（负责人：版本管理；落到 Demo 模板）。
  - 任何会删除、复制文件的替身，必须先重定向 TEMP 并校验真实产物哈希（已在 `stub-check.ps1` 实现；负责人：版本管理）。

## 议题 2：文档措辞精确度导致的评审打回

- **发生了什么**：#149 打回 2 轮，#151 打回 4 轮，#152 打回 1 轮，主要都是文字：预览失败的表现误写、锚点错误、已知限制缺 D199、截图张数写错（18 与 16）、PR 正文的任务表状态过时、列出未做的对照图。
- **根因（推断）**：数字和状态在多处（CHANGELOG、发布说明、PR 正文、README）各自手写，改一处时漏改另一处；状态从任务表抄写，而任务表当时过时。
- **改进动作**：
  - 提交 PR 前，对数字（张数、PR 号、SHA）和状态用一次 `grep` 全文核对，并以 `gh` 的当前输出为准（负责人：版本管理）。
  - 引用任务表前先与已合并 PR 对照，有差异先报告设计角色（本 Sprint 已按此处理，#150）。
  - 对照图、复跑等“没做的事”在初稿就写入披露，不等评审提出（负责人：版本管理）。

## 议题 3：发布日期 PR 与授权的串行等待

- **观察**：每个版本都要经过 RC、Demo、评审、日期 PR、tag/Release 五步，且打 tag 前要等授权；本 Sprint 的等待主要在评审和合并上，没有出现流程错误。
- **改进动作**：本次沿用 v0.5.0 的做法：日期 PR 单独开，合并后在其 squash 提交上打 tag（D21）；授权请求同时附 CHANGELOG 日期修改和当前 main SHA。
