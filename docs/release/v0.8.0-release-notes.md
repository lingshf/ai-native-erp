# AI Native ERP v0.8.0

> **发布日 2026-11-21；tag 与 Release 仍须协调者授权。** 产品代码基线为 main `3720e96`（S8 功能与流程任务全部合并，Full 12/12，run 44956152354）；自 v0.7.0（tag 所指提交 `9f557f7`）到 `3720e96` 共 5 个已合并 PR 的 5 个 squash 提交（#168–#172；`git rev-list --count v0.7.0..3720e96` = 5），其中 #168 是设计提交，#169、#170 是流程文档，#171、#172 是产品与测试提交。按 D21，tag `v0.8.0` 打在日期 PR 合并后的 squash 提交上；基线之后 main 只有文档提交（#173、#174、#175，日期 PR 的基线是 main `fc54f69`），产品代码与 `3720e96` 相同。完整变更对比：[v0.7.0...v0.8.0](https://github.com/lingshf/ai-native-erp/compare/v0.7.0...v0.8.0)（tag 创建后生效）。

本地优先、面向小企业的 AI-native ERP，也可用于会计教学（教学说明可关闭）。SQLite、本机单用户、无登录。**非生产演示版。**

版本号取 minor（0.7.0 → 0.8.0）：新增“从订单开票”用户可见功能和一个只读接口，向后兼容，无新迁移。

## 亮点

- **订单详情显示已开票 / 未开票数量**：已保存订单的订单行表多出两列，没有剩余的行显示“已开完”；每次打开详情读取一次，读取中、失败时订单仍可看（#172）。
- **“开票”入口**：有剩余数量时跳到发票页，所有行开完、读取中或失败时禁用并给出原因（#172）。
- **发票页按订单带入草稿**：方向、往来方、订单号、行信息，数量取每行未开票的部分，已开完的行跳过；外部发票号和日期自己填；只带入草稿，不过账，过账仍按订单逐行匹配校验（#171）。
- 证据（来源：PR 正文）：#171 在真实 Chrome 的 bf6b6a0 上跑过 ui 2/2 变体、e2e 6 个文件 / 13 个用例；#172 在真实 Chrome 的 88e2893 上跑过 e2e 5 个文件 / 8 个用例、ui 2/2 变体、16 对像素对比。这些是 PR 头提交上的结果，不是合并后的 squash 提交。**对照关系要分开看**：#172 的 Chrome 取证 head 就是最终 head 88e2893，其非文档树与合并结果相同（`git diff 88e2893 origin/main -- . ':!docs' ':!design'` 为空）。#171 的 Chrome 取证 head 是 bf6b6a0，它的 `TradeInvoices.tsx` 与合并版**不同**；与合并结果 ad57e6a 做空 diff 对照的是评审修复后的最终 head eb05446（`git diff eb05446 ad57e6a -- . ':!docs' ':!design'` 为空）。eb05446 相对 bf6b6a0 只改了两条错误路径，沿用 bf6b6a0 的主流程 Chrome 证据，**没有对最终版本重跑 Chrome**。

## 面向调用方（HTTP API、CLI、迁移）

- **新增** `GET /api/v1/trade/orders/:orderId/invoicing?company=<公司>`（operationId `getTradeOrderInvoicing`，只读）：返回 `{order, invoiced:[{lineId, invoicedQuantity}]}`；订单不存在 404（`NOT_FOUND`），非 GET 405。
- **未变**：现有订单与发票的请求 / 响应、过账与匹配规则、CLI、日志、端口。依据：`git diff --numstat v0.7.0 3720e96 -- packages/core/src packages/infra/src` 中删除行均为 0。
- **迁移**：无新增，最新仍为 017。依赖无变化。

## 已知限制

- **旧账迁移（M2）仍未完成**：M2-05（演练）与 M2-06（切换）未开始，另需用户授权。
- “开票”只带入草稿，不自动填外部发票号和日期，不自动过账；已开票数量只在打开详情时读取，不自动刷新，在别处过账后须重新打开详情；订单仍限于非库存订单，没有收货。
- 发票页的两条错误路径（链接里的公司不在已加载列表；订单不存在与其他读取失败的区分）由 jsdom 测试覆盖，未在真实 Chrome 逐条验证（#171 正文）。
- 真实 Chrome 的验证在 PR 头提交上，不在合并后的 squash 提交上（见亮点）。
- 分片权重 `trade-gui-zh-red-2`、`trade-gui-en-green-2` 来自两轮本地样本，是估计值，待 CI 耗时复核（#172 正文）。
- Demo 记录与 16 张截图（真实 Chrome，端口 4200 临时账套）：[docs/demo/v0.8.0](../demo/v0.8.0/run-through.md)。基线 `981151d`；截图在第 4 次独占时段采集（前 3 次因旧 dist 构建、徽章符号断言、草稿未隔离而中止，原因与修复见 run-through）。
- 上述数字取自各 PR 正文，发布前未重测。
