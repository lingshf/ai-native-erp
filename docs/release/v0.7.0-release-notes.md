# AI Native ERP v0.7.0

> 发布日期：2026-11-21。产品代码基线为 main `9421906`（S7 功能任务全部合并，Full 12/12）；自 v0.6.0（tag 所指提交 `3548d58`）到产品基线 `9421906` 共 6 个已合并 PR 的 6 个 squash 提交（#155–#157、#159–#161；`git rev-list --count v0.6.0..9421906` = 6），其中 #155、#160 是设计提交，#156 是流程文档；基线之后 main 只有文档提交（#162、#163、#164、#165、#167 与本日期 PR），产品代码与 `9421906` 相同（`git diff --name-only` 只含 docs/、design/、CHANGELOG 与根 README）。按 D21，tag `v0.7.0` 打在日期 PR 合并后的 squash 提交上。完整变更对比：[v0.6.0...v0.7.0](https://github.com/lingshf/ai-native-erp/compare/v0.6.0...v0.7.0)（tag 创建后生效）。

本地优先、面向小企业的 AI-native ERP，也可用于会计教学（教学说明可关闭）。SQLite、本机单用户、无登录。**非生产演示版。**

版本号取 minor（0.6.0 → 0.7.0）：新增订单列表筛选一项用户可见功能和一个迁移（017），向后兼容。

## 亮点

- **订单列表筛选**：按伙伴代码、方向（采购 AP / 销售 AR）、订单日期区间筛选，可任意组合；应用 / 清除 / Enter；加载更多沿用筛选；两个前端校验——伙伴代码格式错误、起始日期晚于截止日期——会就地提示且不发请求；其余服务端拒绝不在本地拦截（#161）。#161 已在真实 Chrome 做过筛选验收（8 个变体，截图与逐像素对比见其正文）。
- **D-7 完成**：`styles.css` 删除，订单号按钮圆角改由页面类规则提供，无可见变化（#159；像素差 0 取自 PR 正文，发布前未重测）。
- **CI 守卫**：新增测试文件必须登记分片权重，否则 PR CI 失败（#157）。

## 面向调用方（HTTP API、CLI、迁移）

- `GET /api/v1/trade/orders` 新增可选参数 `party`、`side`、`from`、`to`；不带这些参数时请求、排序与游标不变。此前 `party` 为未知参数（400），现为合法参数；非法值与未知参数仍为 400。
- **迁移**：最新迁移 016 → **017**（只加索引 `trade_orders_party`，不改表）。已有账套须先显式 migrate 到 017。
- CLI、日志、端口、依赖未变（`git diff v0.6.0 origin/main` 中无 `package.json` 与 lock 变化，迁移目录只新增 017 一个文件）。

## 已知限制

- **旧账迁移（M2）仍未完成**：M2-05（演练）与 M2-06（切换）未开始，另需用户授权；迁移核对页只读。
- 订单列表筛选只有伙伴、方向、订单日期区间；没有金额 / 状态筛选，排序仍按订单号升序；筛选条件不保存。订单页仅限非库存订单；导入、核对确认与备份 / 恢复仍是命令行。
- B4（过账规则）保存成功 / 取消的焦点路径未经真实 Chrome 验证（#135）。
- **CLI 冒烟超时预算（D199）**：3000 ms 未放宽；在整机 CPU 满载（load-cpu）下仍会超时，本版不宣称“整机满载下已解决”。
- Demo 记录与 16 张订单筛选截图（真实 Chrome，端口 4199 临时账套）：[docs/demo/v0.7.0](../demo/v0.7.0/run-through.md)。截图由 Demo 脚本提交 `0d10871` 采集；评审后修订的复跑脚本只经替身验证，未再真实复跑。
- 上述像素差、页面状态数等取自各 PR 正文，发布前未重测。

## 升级与安装

见根 [README](../../README.md) 与[用户文档](../user/README.md)。**新增迁移 017**；v0.6.0 账套先在仓库根目录的 PowerShell 里执行（把示例路径换成你的账套文件）：

```powershell
$db = "D:\erp\my-ledger.sqlite"
npm run storage:admin -- migrate --provider sqlite --file $db
```

再启动。无依赖变化。
