# AI Native ERP v0.12.0（发布说明草稿）

> **草稿，未发布。** 发布日、tag 目标和最终基线在日期 PR 中写定。产品代码基线暂为 main `ab2ba1c`（#219，main Full run 45133620436 绿）；SLOT-02 [#220](https://github.com/lingshf/ai-native-erp/pull/220) 仍在评审，合并后更新。自 v0.11.0 的 tag 目标 `024b7fa` 起，`packages/` 下共 57 个文件（+6255/−3184）。**tag 目标由协调者授权后确定**：按 D21 / D398，先运行 `git diff <基线> <目标> -- packages` 核对，只有产品代码与基线一致才可以打在 Demo / 日期 PR 的 squash 提交上。完整变更对比：v0.11.0...v0.12.0（打 tag 后补链接）。

本地优先、面向小企业的 AI-native ERP，也可用于会计教学（教学说明可关闭）。SQLite、本机单用户、无登录。**非生产演示版。**

版本号取 minor（0.11.0 → 0.12.0）：新增用户可见功能，**含一个迁移（019）**；无依赖变化，不改过账规则。

## 亮点

- **发票详情有了深链接，筛选写进地址栏**：打开详情后地址含 `invoice=`，应用的筛选写成 `party / side / from / to`；刷新、书签、转发地址都能恢复。只替换当前地址，不增加浏览器历史、不弹离开确认。链接有误时有明确提示，不会静默落到别的账套（TINV-07，#208）。
- **订单可按开票状态筛选**：订单筛选栏多了“开票状态”（全部 / 未开票 / 部分开票 / 已开完），可与伙伴、方向、日期组合；API 新增可选参数 `invoicing`。需要迁移 019（TORD-06，#209）。
- **发票页更好读**：筛选栏留白；匹配状态与未结项状态变成彩色徽标；详情合计在宽屏同一行；数量、单价、折扣加千分位（TINV-08，#219）。
- **页头说明与提示统一**：期末结账页和总账四页各有一句页面说明，准入徽标显示“贸易 / 税务”；通用加载 / 失败提示不再出现“主数据”（UI-15 #206、UI-16 #210、UI-17 #213）。

## 需要注意的行为变化

- **刷新后筛选不再清空**：v0.10.0 起发票筛选只在内存里，刷新即清空；v0.12.0 起应用的筛选写入地址，刷新或书签恢复。没有点“应用”的草稿输入不进地址。
- **发票详情不再“不写地址栏”**：v0.11.0 的详情对话框不改地址；现在打开时加 `invoice=`，关闭时去掉。
- **订单“开票状态”列读存储值**：取值规则不变，来源改为新表。

## 面向调用方（HTTP API、CLI、迁移）

- **迁移**：新增 019（新表 `trade_order_invoicing`、一个索引、三个触发器，按已有发票回填）。**已有账套须先 `migrate` 到 019**；迁移在事务内，失败回滚、版本仍为 018。
- **API**：`GET /api/v1/trade/orders` 新增可选 `invoicing=none|partial|full`；非法值、大小写不符、空值或重复键返回 400 `INVALID_REQUEST`（`fieldErrors` 的 `path` 为 `form`）。返回体不变。
- 其他契约、过账规则、依赖不变。

## 已知限制

- **旧账迁移（M2）仍未完成**：M2-05（演练）与 M2-06（切换）未开始，另需用户授权。
- 深链接不记游标与每页条数；筛选参数有任一项无效时整组忽略；有未保存草稿时刷新仍由浏览器离开警告拦截；取消后退丢弃前进历史（D275）。
- 订单页筛选不写地址栏；开票状态只能单选，没有按它排序。
- **性能预算（PG-05，gzip-9，取自各 PR 正文，base 不同不能相加）**：UI-15 入口 +103 B；UI-16 入口 +274 B；TINV-07 入口 +3 B、发票页块 +853 B；TINV-08 发票页块 +219 B、CSS +17 B。与 v0.11.0 相比的净变化未测量，发布前未重测。
- UI-15 / 16 / 17 与 TINV-08 按任务书例外（D375 / D377 / D384 / D406）以 jsdom 验收，没有真实 Chrome 自动取证；视觉由 Demo 截图覆盖。
- Demo 记录与截图：Demo PR 合并后补链接（docs/demo/v0.12.0）。

## 升级与安装

见根 [README](../../README.md) 与[用户文档](../user/README.md)。**v0.12.0 新增迁移 019**：v0.11.0 的账套（018）需执行 `migrate`；该命令只对受支持、且已记录的迁移编号、校验和与表结构指纹都与仓库一致的账套有效，否则以 `SCHEMA_MISMATCH` 退出且不修改账套。更早版本的账套请先按 [v0.10.0 的升级小节](v0.10.0-release-notes.md#升级与安装)处理；本文没有逐个验证更早版本的账套。无依赖变化。
