## 亮点

- **订单列表显示开票状态**：最后一列“开票状态”，未开票 / 部分开票 / 已开完，带符号和文字，不只靠颜色（#179）。
- **订单页深链接**：`#/trade-orders?company=<公司>&order=<订单号>` 直接打开这张订单的只读详情，刷新仍在；公司不在已加载的公司列表中（目前只加载公司列表第一页）、订单号无效、订单不存在都有明确提示和“返回列表”（#179）。
- **发票列表显示来源订单**：有来源订单时是进入订单详情的链接，没有来源显示“—”；390 px 窄屏下订单号换行显示，不隐藏（#181）。
- **五个贸易页统一离开确认**：发票、付款与收款、调整、报表、期间准入有未提交修改时，点链接、导航或浏览器后退 / 前进，只弹一次确认框；取消后地址和草稿保留（#181）。
- **修复**：真实 Chrome 中后退不弹确认框（#181）；过账进行中闪现“过账结果未知”和禁用的“安全重试过账”（FLAKE-06，#180）；从订单开票偶发带入两次并弹出“放弃未保存的草稿？”（FLAKE-07，#180）。
- 证据（来源：PR 正文）：#179 在真实 Chrome 的 470fb6d 上跑过 e2e 5 个文件 / 8 个用例，16 对 base / head 截图；最终合并 head 是 d4967af，评审修复只涉及导航与历史逻辑，沿用 470fb6d 的时段证据（D270），这部分只由 jsdom 历史轨迹用例证明。#181 在真实 Chrome 的 5f3be0a 上跑过 e2e（zh-red-2、en-green-2 两个文件合计 2/2）和 12 对 base / head 截图，5f3be0a 就是最终 head。这些是 PR 头提交上的结果，不是合并后的 squash 提交。

## 面向调用方（HTTP API、CLI、迁移）

- **订单列表** `GET /api/v1/trade/orders`：每个列表项新增必填 `invoicing`（`none` / `partial` / `full`），与 `GET …/orders/:orderId/invoicing` 推算的状态一致（#179）。请求参数、排序、分页不变。
- **发票列表**：每个列表项新增可空 `orderId`（来源订单号）（#181）。
- **未变**：订单与发票的请求 / 响应其余字段、发票预览 / 过账请求、过账与匹配规则、CLI、日志、端口。新增字段是响应里的增量：能忽略未知字段的客户端无需改动；v0.8.0 的两个列表项 schema 是 z.strictObject，仍用旧严格校验的客户端会拒绝带新字段的响应，需要更新。依据：`git diff --numstat v0.8.0 6478d10 -- packages/core/src packages/infra/src` 只涉及 trade-documents 的三个文件。
- **迁移**：无新增，最新仍为 017。依赖无变化。

## 已知限制

- **旧账迁移（M2）仍未完成**：M2-05（演练）与 M2-06（切换）未开始，另需用户授权。

- **性能预算超出，已接受**：入口 gzip +375 B（预算 +300 B，D284）、CSS 实测 +106 B，超预算 6 B（D295 已接受），数字取自 #181 正文，发布前未重测。
- 订单列表只显示开票状态，没有按开票状态的筛选 / 排序；发票列表的来源订单列没有筛选。
- 订单页和主数据编辑器的离开确认文案与其他五页不同。
- 真实 Chrome 的验证在 PR 头提交上，不在合并后的 squash 提交上（见亮点）。
- `leave-guard-history.test.ts` 的分片权重 150 是手工估计，待 CI 耗时复核（#181 正文）。
- Demo 记录与截图：待补（Demo 完成后在 Demo PR 加入链接）。
