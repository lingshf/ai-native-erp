> **草稿（RC，MCF-02，D573）**：未发布，没有 tag，没有 GitHub Release；发布日期与 tag 须经用户授权后才填。取代旧 RC `release/v0.22.0`（固定在 `3566ddb`，已过时）。新 RC 分支 `release/v0.22.0-rc2`，**RC 范围终点** `13a4199ec1e6b45904f0106e905d7d5cf21fb11c`（[#396](https://github.com/lingshf/ai-native-erp/pull/396)，Full 绿，run 45529505073）。v0.21.0 的 tag 指向 `01b16dbf36dd4feab80aee05f9583cfe9bc1de13`（在 `release/v0.21.0`，不在 main 上），与范围终点的合并基是 `3ae4848d36c4c06c2e208173e58ed2cac3771564`。v0.22.0 的 tag 目标待协调者决定（D21/D484），此处不预设。

本地优先、面向小企业的 AI-native ERP，也可用于会计教学（教学说明可关闭）。SQLite、本机单用户、无登录。**非生产演示版。**

版本号取 minor（0.21.0 → 0.22.0）：有用户可见的功能与行为变化。**无迁移（最新仍是 020），无依赖变化**，已有账套不需要 migrate，不改过账规则与任何金额、数量口径。

## 亮点

- **付款与收款页**（TSET-01，[#320](https://github.com/lingshf/ai-native-erp/pull/320)）：已选项已不在未结项中时，表格上方给出警告和“移除这些项”；只移除缺失项，焦点回到“刷新列表”。
- **付款条件天数整数校验**（TMAS-01，[#342](https://github.com/lingshf/ai-native-erp/pull/342)）：到期天数、折扣天数只接受 0–3650 的整数，`30.0`、`1e2`、`0x10` 等不再被静默改写后保存。
- **总账明细筛选**（BUG-01，[#382](https://github.com/lingshf/ai-native-erp/pull/382)）：没有维度代码时“维度值”不可填，不再误显示“选择无效”。
- **AI 助手**：BUG-02a/02c（[#387](https://github.com/lingshf/ai-native-erp/pull/387)）已有回答时清理失败不再覆盖回答，取消先于工厂失败时提示“已取消”；**SEC-02（[#391](https://github.com/lingshf/ai-native-erp/pull/391)）交给 Copilot SDK 的环境变量改为显式白名单**（见下）。
- **贸易单据只读接口**（BUG-03a/b，[#383](https://github.com/lingshf/ai-native-erp/pull/383)）：仅接口层校验顺序与 ID 校验变化，界面不变。
- 大量内部拆分（REFAC-13..34 等）与开发工具（FLAKE-09、MEAS-02、SLOT-06）：行为不变，无用户可见变化，逐项见 [CHANGELOG](../../CHANGELOG.md)。

## 需要注意

- **SEC-02 是行为变化**：AI 适配器只交出明确设置且非空的 `COPILOT_GITHUB_TOKEN`；以前靠 `GH_TOKEN`、`GITHUB_TOKEN` 等继承变量使 AI 可用的部署，升级后 AI 可能不可用（`AI_UNAVAILABLE`，手工记账不受影响）。迁移：改设 `COPILOT_GITHUB_TOKEN`，不保证恢复以前所有认证方式。子进程环境**不是只含白名单**（SDK 与 Windows 会补入少量变量），不应称为“已隔离”。详见 [AI 助手 §3、§5](../ai-assistant.md)。
- **已知未验证（D571）**：原生 CLI 离线启动只有 Linux 证据，Windows 未验证；真实认证兼容、代理与自定义 CA 未验证。
- **无迁移**：v0.21.0 的账套可直接使用。
- **证据口径**：本 RC 目前只有文档与 CI 证据；Demo（真实浏览器截图与键盘取证）尚未进行，需要先经协调者批准时段（D480）。Demo 完成前不得把本草稿当作已验收。
- **用户文档缺口**：BUG-01 的总账明细筛选在 `docs/user/` 没有对应页面，本 RC 只在 CHANGELOG 与本说明记录。
