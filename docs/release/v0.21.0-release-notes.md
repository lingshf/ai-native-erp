# AI Native ERP v0.21.0

> 草稿（RC，DEMO-22）。tag 由协调者授权后按 D484 打在已批准的 RC 最终头（`release/v0.21.0`），不打在 main 的 squash 提交上；tag 对象、发布日与 tag 对 tag 的数字在日期 PR 中补写。RC 范围终点固定为完整 SHA `3ae4848d36c4c06c2e208173e58ed2cac3771564`（[#317](https://github.com/lingshf/ai-native-erp/pull/317)）。v0.20.0 的 tag 指向 `90c762f05de39723852d1a381058301cab4da997`（`release/v0.20.0`，不在 main 上，树与 main 上 #310 的 squash 提交相同）。

本地优先、面向小企业的 AI-native ERP，也可用于会计教学（教学说明可关闭）。SQLite、本机单用户、无登录。**非生产演示版。**

版本号取 minor（0.20.0 → 0.21.0，D514）：TLIST-06 让付款与收款页多了一个按钮，是用户可见的小功能。**无迁移，无依赖变化**，已有账套不需要 migrate，不改过账规则与任何金额、数量口径。

## 亮点

- **付款与收款页多一个“刷新列表”按钮**（TLIST-06，[#316](https://github.com/lingshf/ai-native-erp/pull/316)）：在“核销分配”页签的表格之前（英文 “Refresh list”），重读已加载的未结项。已选的未结项和核销总额保留，草稿不清空；确认过账结果未知时按钮仍可用，不影响原请求。Tab 顺序多一站。
- **开发工具与重构**：SLOT-05（[#312](https://github.com/lingshf/ai-native-erp/pull/312)）窗口门禁快照工具；REFAC-12（[#311](https://github.com/lingshf/ai-native-erp/pull/311)）付款与收款页组件拆分，行为不变。均无用户可见变化。

## 需要注意

- **无需 migrate。** v0.20.0 的账套可直接使用。
- **体积**：见 Demo 的 run-through（窗口外用 `scripts/measure/bundle-measure.mjs` 测得，路由与 chunk 分列）。**D519 例外：** Sprint 累计 `TradeSettlements` +841 B 超过 +200 B，其中 +775 B 来自 REFAC-12 在同一路由上的拆分（已按其自身预算评审批准）；TLIST-06 本身 +66 B，首屏 +2 B（D454 ≤10 B）。协调者已放行，产品代码未改。
- **验证说明（D521）**：Demo 窗口内 K2（选择与核销金额保持）的断言无效、不属于窗口验收，原因是 capture 脚本的选择器缺陷（取到了选择 checkbox，其值 `on` 并非金额）。脚本已修复，但没有在真实浏览器里重跑。真实浏览器证据只覆盖键盘焦点路径与 Enter / 空格激活；“刷新后选择与金额保持”由产品测试 TLIST-06 S3 证明（结果见 run-through）。
- **证据口径**：TLIST-06 的单元用例是 jsdom；真实 Chrome 的 Demo 证据（付款与收款页 × 中 / 英 × 1440 / 390 px 的截图与真实按键记录）见 [Demo](../demo/v0.21.0/README.md) 及其 run-through。
