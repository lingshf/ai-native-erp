# v0.3.0 Sprint 回顾（UI-1）

基于事实的草稿，供团队讨论，非结论。

## 做得好

- 设计规范、原型和对比度检查脚本先于实施，13 项任务按依赖逐页合并，没有推倒重来。
- UI-08 用同一夹具、同一脚本对改前改后逐像素比较，并要求业务状态指纹一致，把“只改样式”变成可验证的结论。
- 采集中发现的差异（原生下拉框的栅格化抖动）被追到根因（`--disable-partial-raster`），而不是放宽阈值。
- R6b 先剖析再改（Chrome 冷启动是抖动来源），Full 分片问题有数据支撑。
- 发布 PR 评审逼出了与代码口径一致的说明：迁移判定顺序、日志 `errorType`、点击区尺寸。

## 需要改进

- 任务表（`design/tasks/README.md`）在任务合并时没有同步状态与 PR 链接，直到发布评审才补上。
- 发布文档的概括性承诺（“所有点击区 ≥ 44px”“行为与 v0.2.0 相同”）超出了实测范围，评审两轮才收窄。
- Demo 中的命令第一次没有在 PowerShell 里实际执行，占位符直接写成 `<…>` 导致无法运行。
- R6 之后 Full 分片仍需 R6b 重开（D38），说明首次调整缺少对 runner 冷启动的剖析。
- 日志类型变化（#81）属于运维可见变化，当时的 PR 说明没有写明旧值到新值的映射。

## 讨论问题

1. 任务合并的检查清单是否增加“任务表状态与 PR 链接”一项？
2. 发布文档中的数字性、全称性断言是否要求给出来源（测试或截图）？
3. Demo 中的命令是否一律要求在评审前实跑并记录？
4. UI-09 的优先级相对 M2-05？
